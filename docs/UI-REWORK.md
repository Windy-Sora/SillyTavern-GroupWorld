## 1. 目标与边界

目标：日常操作集中、所有功能可发现、配置层级清晰、窄侧栏长度可控。

- 保留现有功能与数据行为，延续 SillyTavern 主题；不增加新业务功能。
- 不改 Provider ID、DSL、EXT_KEY、全局拦截器或导入导出协议。
- 本轮不设计新的模型配置能力、全局搜索、收藏系统或跨系统撤销。
- 先在 GroupDirector 完成，检查后复制同步 release，不在 release 单独开发；稳定后另行同步 GroupWorld。
- 不把界面隐藏等同于功能停用。导航只控制显示，业务启用状态仍由原设置决定。
- 保留经典界面，提供经典/新版切换；本轮不设经典版退役期限。
- 经典版维持原布局并接收必要修复，体验改进集中在新版；两种界面共享最新版业务逻辑。

### 1.1 双界面过渡方案

本稿第3至6节的新导航、布局和迁移映射主要描述新版。经典版继续使用原抽屉布局，
只补切换入口、必要的生命周期清理和共享操作适配，不另存一套业务状态。

- 两边页头均有可发现、键盘可操作的“界面：经典 / 新版”切换入口。
- 过渡期未设置偏好时统一默认经典（包括已有用户）；用户主动选择新版。
- 界面选择保存在当前浏览器、当前站点的版本化本地偏好中，不进入 extension_settings、
  配置档、群聊导出或资源库，不随应用配置而改变。它不是账号间同步偏好；若实现可取得
  可靠的宿主用户标识可隔离用户，否则明确同一浏览器站点共享，不能推断为用户独立设置。
- 存储不可用或值无效时默认经典；本次选择仍可在会话中生效，写入失败不能阻断界面使用。
- 只挂载一套活动界面，共享系统实例、数据、字段标识和动作入口。不以 CSS 隐藏另一整套
  DOM，不复制运行时、不重复注册宿主事件，也不克隆一套源码独立修业务问题。
- “单一编辑入口”在新版内部执行；经典版可保留原有快捷编辑布局，但共用同一业务动作。
  新旧两套编辑器不同时挂载，经典版也不能执行已经被新版修复替代的旧业务逻辑。
- 切回经典只恢复界面，不回滚版本、配置、聊天数据或已完成操作。

### 1.2 切换生命周期与保护

切换流程：检查任务和编辑状态 → 处理草稿/待保存 → 准备目标模板 → 销毁旧视图绑定
→ 挂载并初始化目标视图 → 成功后记录偏好。准备失败保留原界面；初始化失败清理
目标视图并恢复来源版本，保留来源偏好和可恢复草稿，显示错误。任意时刻最多一套绑定。
准备模板不得提前初始化 section 或发起业务操作。

首版有依赖视图回调的生成、导入、应用、保存等操作正在运行时，阻止切换并说明
具体任务；不自动取消任务，不靠按钮 disabled 或固定时间判断结束。试点须登记其
覆盖的操作生命周期。未迁移页无法可靠判定时不得猜测安全，显示限制，待操作结束后重试。
当前宿主聊天生成也应在可观察的运行期间阻止切换。实现不了可靠保护的路径不能开放热切换。

草稿处理遵循6.2节。切换是会销毁 DOM 的动作，不等同于普通切页：未保存编辑须保存、
明确放弃或取消切换；无保存能力只允许放弃/取消。经典版编辑器也必须纳入此保护，
不能因其尚未迁移就静默丢弃。无法完整识别的编辑路径是热切换开放的阻断项。
不能把刷新浏览器作为绕过这些保护的自动操作。

业务生命周期与 UI 生命周期分离：卸载只清理当前视图事件、订阅、observer、timer
和旧 DOM 引用，保留系统状态。全局兼容回调委托当前活动视图；旧异步回调需检验
挂载代次，不能在新视图中重复通知或刷新。重复切换不重复执行 section 注册代码。

模式切换后新版恢复合法的最后导航，经典版恢复经典卡片状态；两者分别保存布局状态。
应用配置后的 reloadSettingsUI 必须重建当前活动版本，不读取配置档来决定界面版本。

## 2. 当前结构与问题

现有一个插件外层抽屉、五个业务抽屉、29 个 data-card 节点（含嵌套卡片）。
另有仪表盘、七个动态数据面板、单独的世界书展开区和隐藏的快速开始容器。

主要问题：

1. 顶部并列数据摘要、生成操作、配置维护、群聊导入导出和帮助入口。
2. 仪表盘不只是摘要，还承担编辑、生成和库管理；功能卡片存在重叠入口。
3. 数据操作、业务设置、Prompt/Schema、资源交换混在同一卡片中。
4. “反应”“工具”难以准确表达自定义 Agent、模型连接等功能归属。
5. 全局配置、当前聊天数据和跨聊天资源缺少稳定的范围提示。
6. 卡片折叠状态虽已持久化，但展开后仍是长页面；不能仅靠增加折叠解决。

## 3. 导航候选方案与验证要求

采用六个一级区域；每次只显示一个区域，区域内每次只显示一个功能页。
首次打开进入概览，之后恢复有效的上次区域/功能；每个区域分别记住上次功能。
未知区域回到概览，区域内失效功能回到该区域默认页。概览是一个页面，
运行状态、最近选人结果、常用操作、数据摘要是按此顺序排列的四个区块，不是二级页面。
概览首先回答“导演是否正常工作”：显示是否启用、模式、最近选人、已有理由，
以及可获得的未执行/失败原因，并直达发言规则和导演账本。没有记录显示“暂无决策记录”；
没有原因显示“未记录原因”。历史成功不能代表当前运行正常，不为 UI 增加选角推理能力。

运行状态区提供轻量情境提示：无决策记录时直达发言规则；实际校验到连接缺失时
直达对应模型连接；非群聊时解释可用范围，不用一组零值代替说明。
档案、记忆和世界书数量只描述数据准备情况，不能代表导演整体就绪，也不能都列为
必做步骤。Formula 本地评分模式与需要模型的功能分别判断；继承宿主连接不等于
缺少配置。详细配置说明归帮助，当前阻碍和下一步入口留在当前页。

| 一级区域 | 二级功能页 |
|---|---|
| 概览 | 单页：运行状态 → 最近选人结果 → 常用操作 → 数据摘要 |
| 导演 | 发言规则、剧本与连续性、上下文、强制发言 |
| 角色与剧情 | 档案、记忆、NPC、身份、总结、蓝图、批判、账本、变量、世界书 |
| 自动化 | 消息反馈、轮次反馈、能力模块、自定义 Agent、脚本执行器、自动化记录 |
| 配置与资源 | 模型连接、配置档、可复用库、导入导出 |
| 高级与帮助 | 提示词数据源（原自定义提示词）、用户扩展、Provider 参考、模板运行设置、模板测试、执行追踪、使用帮助 |

名称说明：能力模块说明中保留 Capability；消息反馈说明为“每条角色消息后”，
轮次反馈说明为“每轮对话后”，实际触发条件仍以现有系统为准。
“提示词数据源”提供可复用内容与结构化数据，不是所有功能的 Prompt 编辑中心；
各功能 Prompt 仍在所属功能页。帮助始终有页头直达入口，无需先理解高级功能。

三类记录必须显示各自用途：导演账本记录导演每轮选人、计划及状态，供复盘剧情；
自动化记录来自 PostSpeech 的消息/轮次决策，查看能力动作及执行情况，不等同于
自定义 Agent/脚本的完整日志；执行追踪是运行时 Agent 阶段、耗时和错误诊断，
仅在采集开启且有记录时展示。导演页直达账本，自动化页直达自动化记录。

“角色与剧情”功能选择器分为角色/剧情/世界三组，避免十个横向标签：
角色＝档案、记忆、NPC、身份；剧情＝总结、蓝图、批判、账本；世界＝变量、世界书。
采用原生 optgroup 分组。每个功能标题下有一句用途说明，首次进入也能理解用途。
跳到模型连接、库或导入导出时保存来源，并显示“返回角色档案”等明确入口；
返回恢复来源页面的折叠和滚动位置，不产生新的业务操作。
关联跳转携带目标上下文：档案页定位 Profile 连接，NPC 页进入 NPC 库，
功能页进入导入导出时选择对应类型；仅导航定位，不应用配置、不执行生成或导入。

正常宽度（建议以插件容器 600px 为切换起点，后续手动点测微调）使用
左侧一级导航和右侧功能内容。窄侧栏使用两个有可见标签的原生选择器：
“区域”“功能”。六个区域全部可见于选择器，不使用横向滚动标签。
断点依据插件实际容器宽度，不依据整个浏览器视口；两种布局使用同一份内容 DOM。

宽布局试点比较两个候选：A 为一级导航加功能选择器（下方草图）；B 为左侧仅展开
当前区域的分组二级功能。角色/剧情/世界只是分组标题，不构成第三层导航。
依据查找任务完成情况、菜单操作和内容可用宽度确定，不展开全部区域的所有功能。
窄栏以双选择器为基础；概览摘要、情境提示及关联入口直接到达具体功能或对象，
不能只跳到区域首页。六区划分及名称通过第8节验证，迁移完整不等于分类易懂。

## 6. 页面交互与状态约定

### 6.1 层级、控件语义与操作后果

| 层级 | 内容 |
|---|---|
| 直接可见 | 功能开关、当前状态、数据、主要操作、错误与禁用原因 |
| 功能设置 | 自动条件、数量、预算、并发等常规参数 |
| 高级编辑 | Prompt、Schema、包装模板、代码 |

不强制每页都有三层；单一编辑用途的简单页可以平铺。第4节的“收起内容”
按此表拆分，而不是把常规参数全部塞进高级编辑。
范围标签之外，操作旁必须说明后果：功能设置“影响所有聊天”；记忆编辑
“仅修改当前聊天”；保存到库应经对应接口核对后明确是否同时改变当前聊天；
应用配置档显示所选模块、合并策略和不覆盖的内容，不能笼统写“全部覆盖”。
应用模板涉及全局设置时在确认处单独提示。试点验收需逐项对照实际写入，
不依据页面所在区域推断作用范围。

范围与保存方式同时贴近编辑块：功能设置显示“影响所有聊天 · 修改自动提交”；
手动档案编辑显示“仅当前聊天『聊天名』 · 尚未保存”。自动提交不等于已持久化，
只有获得保存确认后才能显示“已保存”；无法观察确认时不得宣称保存完成。
不得给即时保存字段附加无实际回滚能力的“保存/取消”。模型页把 useCustom 明确
表达为“连接方式：继承 SillyTavern 连接 / 使用独立连接”，它不是 Agent 启用开关；
继承状态也应可见，不能以空白配置区暗示未配置。

| 档案页面情境 | 主要操作 | 批量操作 |
|---|---|---|
| 尚无档案 | 可突出既有生成操作，并注明当前群聊启用角色范围 | 执行前说明模型调用与对象数量 |
| 部分档案缺失 | 缺失角色的行内生成、已有档案的查看/编辑 | 全部重生成置于次要区或更多 |
| 大部分档案已就绪 | 查看、编辑、检测档案变化 | 全部重生成置于次要区或更多 |

概览与功能页采用相同操作优先级，不通过概览绕开覆盖说明。
批量重生成确认展示当前聊天名称、启用角色数、其中已有档案的数量及成功结果将
替换的内容，并说明会调用模型；不估算无依据的费用或耗时。取消不发起业务调用。
确认依据实际目标快照；提交前范围或聊天变化时重新校验，不能静默扩大范围。
不新增“仅生成缺失档案”批处理；单角色入口沿用已有能力，覆盖已有内容同样说明后果。

显示名称候选“导演模式与发言规则”“强制发言处理”“身份提示词”“剧情评估（批判）”
和“配置预设（配置档）”在任务试点中验证，未验证前不统一改名；内部标识保持不变。

### 6.2 导航、滚动与草稿

| 事件 | 约定 |
|---|---|
| 明确点击功能入口 | 显示目标功能，初次从顶部开始；保留草稿与折叠，让标题或指定目标可见后再聚焦；不聚焦屏幕外的标题 |
| 原生选择器导航 | 选择与提交时机明确；浏览选项时不反复转移焦点或重建选择器；若选择即切页，提前说明并保留选择器焦点；无法保证可预期操作时采用明确“前往”按钮提交 |
| 从关联页面返回 | 同一聊天会话内恢复来源控件、滚动及折叠，优先让来源控件可见；目标失效则回退到可见标题并说明；不同时恢复页面中部滚动又聚焦页首 |
| 点击具体字段/错误直达 | 忽略原滚动位置，先显示区域与功能，再展开目标折叠区，定位并聚焦目标；不存在则停在页标题并说明 |
| 前往模型连接/库/导入导出 | 定位对应 Agent、资源类型或交换类型；会话内维护返回栈，含来源功能/对象/控件/滚动；避免自跳转循环；来源失效回到合法默认页 |
| 切换聊天 | 保留导航功能，但清除旧聊天滚动上下文；草稿按聊天标识和对象标识隔离，不能填入新聊天对象 |
| 应用配置档 | 必须在真正应用前检查未保存编辑；提供保存后继续、放弃后继续、取消；保存失败停止应用，放弃只在用户明确选择后执行 |
| 其他面板重建/语言变更 | 显式采集并恢复兼容草稿，或在销毁 DOM 前走同样保存/放弃流程；禁止仅依赖隐藏 DOM |

即时保存字段不当作未提交草稿；仍在保存中的操作必须等待其结果再决定是否重建。
“等待结果”只适用于有可观察完成结果的接口。普通 saveSettings() 当前不返回保存
确认，不能把 await 该函数或等待固定毫秒数当成持久化完成。已确认保存失败时
停止会覆盖输入的配置应用并保留输入；无法确认时显示“保存状态未知”，允许
用户取消或明确选择继续覆盖，并说明可能丢失尚未确认的修改，不得无限等待。
导航状态写入也不能被误当成当前业务编辑的保存确认。
手动保存编辑器在各页面迁移时登记 dirty、save、discard、scope/objectKey；
无保存能力的草稿只提供放弃/取消，不显示无效的“保存”。新增草稿缓存仅在内存，
不将密钥或聊天内容存入 uiState。聊天切换不能依赖可取消的宿主事件：离开时
可保留隔离草稿，返回原聊天且对象仍有效时提示恢复；对象已删除或状态变更时
提示失效/冲突，不自动套用旧草稿。刷新浏览器不承诺恢复未保存草稿。
应用配置档的“取消”必须发生在业务写入前；reloadSettingsUI 内才拦截已太晚。
“保存后继续”按编辑器顺序执行，不是跨系统原子事务。某项失败就停止后续保存
和配置应用，保留失败及尚未处理的草稿，并列明已经保存的项目；不回滚前面已
成功的独立保存，不提示“所有修改均已撤销”。等待期间聊天或编辑对象发生变化
时重新校验上下文，不继续把原草稿保存到新对象。

返回栈项额外包含来源聊天标识。聊天发生变化后，返回仅导航到对应功能在当前
聊天的页面，不恢复旧对象、焦点目标或旧滚动；明确提示上下文已变化。
此约定不会自动切换回旧聊天，也不会清除按聊天隔离的草稿。

导航持久化仅包括版本、区域和每区最后功能；滚动、返回栈、草稿仅为会话状态。
异步数据渲染完成后恢复滚动，不能用任意固定延迟假定 DOM 已就绪。
焦点验收覆盖宿主抽屉、粘附导航与弹层遮挡；原生控件不自动代表键盘流程通过。

### 6.3 异步结果与状态显示

| 状态 | 显示与操作 |
|---|---|
| 模式不适用 | “仅 LLM 模式适用”等明确说明，提供模式设置入口，不自动切模式 |
| 功能关闭 | “已关闭”，显示启用入口及已有数据；是否允许读写遵守既有接口 |
| 缺少连接 | 仅在实际校验到缺失时提示并直达模型连接；继承宿主不等于未配置 |
| 正在运行 | 由真实调用生命周期驱动，阻止同一操作重复提交；跨页持续；Promise 结束只代表调用结束 |
| 操作结果 | 从本次执行和写入结果表达成功、失败、跳过或未知；按钮恢复、Promise 正常结束、现有 ready 数量都不能证明更新成功 |

这些状态可以并存：数据留存与运行状态分开显示，不用一个颜色覆盖所有含义。
每次操作关联聊天标识、对象标识及调用实例；完成时仅刷新匹配的当前视图。
旧聊天结果是否保存、取消或判定过时遵守已有系统契约；UI 不重路由结果、
不重试旧任务，也不在新聊天弹出误导性的成功提示。切页不是取消操作。
缺少可读取状态时只增加局部动作适配，不建设新任务调度系统。

本次任务结果与现有数据状态分别记录和呈现，不挤进一个互斥状态枚举：

| 维度 | 最小表达 |
|---|---|
| 对象执行结果 | 成功、失败、跳过、未知；附可获得的真实原因 |
| 对象写入结果 | 已应用、未应用、因过时拒绝应用；无法确认则未知 |
| 现有数据 | 是否仍有旧数据可用；不用于反推本次成功 |
| 批量汇总 | 根据本次逐对象结果汇总；部分成功是汇总结论，不与对象状态混为一类 |

档案现有生成路径可能返回空结果而不写入，也可能内部处理异常并保留旧就绪档案。
试点允许为原调用链补充最小结果明细，不改变生成范围、写入策略或新增业务存储。
只有本次成功且确认已应用才能计入“已更新”；失败但保留旧数据应明确说明；
过时未应用、跳过和未知单列，不能归为成功。无法取得明细时显示未知，不编造计数。
结果示例仅在真实数据支持时使用：“本次更新2个，失败1个，跳过1个；失败角色原档案仍保留。”
功能页保留本次结果摘要与允许的重试入口，不只依赖短暂通知；按任务/聊天隔离，
不要求跨刷新持久化。普通完成提示使用适当的状态消息机制供读屏感知，不为通知抢焦点。

### 6.4 通用约束

- 新版同一字段只有一份可编辑 DOM；快捷入口导航或调用同一操作，不克隆字段和 ID。
  新旧界面互斥挂载；经典版的原有快捷入口共用操作与结果处理。
- 数据操作区在前，功能设置其次，高级编辑默认折叠；编辑页内至多两层显示导航。
- 范围标签贴近操作：应用配置为全局，库保存为可复用资源，改当前记忆为当前聊天。
  导入模板等同时影响设置的操作要显示双重范围。
- 删除、清空、覆盖沿用确认；不把破坏性操作放成主要按钮。
- 用已有真实运行信号显示忙碌/错误/禁用原因；无法观察时显示未知，不猜测完成。
- 切换导航不能启动生成、保存业务数据或清空表单。异步操作跨页继续，返回后显示结果。
- 手动编辑草稿切页保留；切聊天时不得把旧草稿写入新聊天。已有保存/放弃契约不变。
- 非群聊仍能访问全局配置与帮助；当前聊天数据页显示明确空状态，禁用依赖群聊的操作。
- 使用原生 button/select/label，导航有当前项语义；焦点按6.2节处理且可见；
  高级区展开状态有 aria-expanded；不要求用户必须通过鼠标悬浮发现入口。
- 不新增业务存储。UI 导航状态放在现有 uiState 的独立版本化字段，非法值回到概览；
  卡片状态保留旧键作为迁移参考。导入他人的配置不得导致导航到不存在的目标。
  此处 uiState 仅指布局导航，界面版本偏好按1.1节单独存本地；经典与新版布局键不覆盖。

### 6.5 最小视觉约定

默认顺序为功能名称与用途、当前对象和状态、主要操作、数据内容、设置与高级编辑；
简单编辑页可平铺。折叠标题可显示自动处理、连接方式等真实配置摘要，不复制编辑控件。
范围标签靠近对应操作和编辑块；不以缩小字体或点击区域解决窄栏溢出。
沿用宿主主题，实际验证长中英文、放大显示、焦点与状态辨识；文字草图不代表视觉验收。

## 8. 分批执行与完成标准

1. 第一阶段（本文）：完整归属、布局、重复入口处理与依赖约束，供评审。
2. 第二阶段：建立经典/新版互斥装配、切换入口和保护，再建新版导航骨架与兼容路由。
   先验证两次往返切换和失败恢复。未迁移功能在新版内复用旧卡片展开并定位，显示
   返回入口；不为访问旧卡片自动切整套 UI，不先搬混合卡片再重新拆分，不复制 DOM。
   只有完成1.2节保护的路径才开放热切换；此项不要求所有功能先完成新版布局迁移。
3. 第三阶段：先完整迁移档案试点，覆盖数据编辑、批量生成、库/模型跳转与返回、
   草稿、配置应用前拦截、窄栏及真实任务状态，再依次迁移角色数据、剧情数据、
   导演/自动化、配置/工具。每批一个可运行提交，其余页面继续走兼容路由。
   迁移清单逐项记录旧入口、新入口、共享操作及刷新/清理归属；试点未通过不扩展。
   档案试点必须补齐本次结果汇总和批量覆盖确认，再评估是否推广页面结构。
   每个功能一旦迁移，新版内的旧编辑入口立即转发到新页；经典版仍保留原入口。
   兼容回调根据活动版本处理，不能在新版中再次创建旧编辑控件。
   草稿保护登记表必须列出已覆盖编辑器及未覆盖旧编辑器。档案试点须覆盖档案页
   及其旧快捷入口；整面板重建仍会影响其他旧页，不得宣称全插件草稿安全。
   未接入保护的编辑器作为已知限制保留在验收报告中；涉及其编辑内容的重建需
   明确提示先处理原页编辑，不能因档案试点通过而把其他旧页视为已验证。
4. 第四阶段：全部功能覆盖后清理新版的旧编辑区和兼容路由；经典布局继续保留。
   仅删除两种版本都不再使用的逻辑，共享动作与必要修复同步覆盖两边。
5. 第五阶段：完整回归、双界面操作清单、手册与回退说明同步；再决定同步稳定版。

未来验收场景：

| 场景 | 预期 |
|---|---|
| 首次打开 / 恢复上次页面 | 首次概览；再次恢复有效目标，无效目标回退 |
| 各区域记忆与返回来源 | A 区切功能后去 B 再回 A，恢复 A 的选择；模型/库返回恢复来源折叠与滚动 |
| 字段直达与草稿重建 | 目标折叠区展开并聚焦；配置应用取消不写入；草稿保存失败不继续；重建不静默丢草稿 |
| 返回途中切换聊天 | 仅返回当前聊天的对应功能，不恢复旧对象/滚动，不自动切回旧聊天 |
| 多编辑器保存后继续 | 前项成功、后项失败时不应用配置；清楚列明已保存项并保留剩余草稿 |
| 保存失败/确认未知 | 失败阻止配置应用；未知不误报成功、不无限等待，继续覆盖须明确选择 |
| 已迁移功能的旧入口 | 新版旧统计、按钮和刷新回调只导航或更新新页；经典版保持原入口并调用共享动作 |
| 初始版本与偏好 | 无偏好默认经典，刷新后恢复选择；应用/导入配置不改变界面版本；存储不可用仍能使用 |
| 经典 → 新版 → 经典反复切换 | 始终一套 DOM、一次业务调用，无重复 ID/注册/监听；数据和业务设置不因切换改变 |
| 草稿/运行任务期间切换 | 按保护处理；取消不卸载也不改偏好，保存失败阻止切换；运行中不隐式取消任务 |
| 模板准备或挂载失败 | 原界面保留或来源版本恢复，不留半套目标 UI；偏好不提前写入，草稿不静默丢失 |
| 经典与新版执行相同操作 | 保存、生成、导入导出共用业务行为和必要修复；两边结果与失败提示一致 |
| 点击档案统计 → 编辑 → 保存 | 到同一个档案页，保存反馈与摘要同步，无第二份编辑表单 |
| 概览快捷生成与页内生成 | 同样的准确命名、操作优先级、覆盖确认、忙碌和结果处理；取消不调用，不重复执行 |

## 9. v3 实施约定的代码核对

| 证据位置 | 核对结果 | 对设计的约束 |
|---|---|---|
| index.js：saveSettings / saveSettingsConfirmed | 普通封装调用防抖保存且不返回确认；另有依赖 SETTINGS_UPDATED 的确认保存封装，用于部分系统 | 不假设所有设置均可 await 确认；区分失败、未知和已确认 |
