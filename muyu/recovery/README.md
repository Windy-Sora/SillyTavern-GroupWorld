# 操作检查点与中断恢复

已支持本地核对后重新批准剩余配置／数值变量步骤，第三轮新增普通全局配置的冲突安全撤回。不提供自动续跑或自动回滚。不是针对某类内容绕过模型拒绝，而是对网络错误、模型拒绝、刷新、进程退出等中断统一保守处理。

## 当前范围

- 普通配置动作及整单动作使用原有精确批准协调器；其他资产编辑、生成和只读模型任务暂未接入检查点。
- 写入前等待 IndexedDB 事务提交，然后重新检查目标与草稿。整单每步执行前、执行结果返回后各记录一次；结果检查点失败停止后续步骤。
- 操作结果与记录结果分开：结果落盘失败不能把已执行操作改称未执行，也不能自动撤销。页面退出不保证最后一条写入能完成。
- v1 记录继续只读兼容。新记录为闭合 v2 DTO：除原有操作范围、步骤及回执外，新增完整的纯数据恢复意图（受支持配置的原基线／请求值、数值变量的原定义／值与请求）、父记录及续接操作 ID。不存授权、连接密钥、页面身份、草稿 token、完整工具轨迹、思考或脚本正文。差异与恢复意图可能包含私人 Prompt／变量文本，以明文存储。脚本整单、专用副作用配置和无法完整表示的旧草稿不生成恢复意图，不能从截断回执推导执行请求。
- `applying` 仅表明已记录即将派发；若中断后没有结果，必须按结果不确定处理，不能保证工具已经或尚未执行。`not_started` 只针对未派发的后续步骤。

## 存储与界面

复用自动保存对话开关。关闭后不新写检查点，操作仍可执行，但没有本轮持久恢复保障；不会删除旧记录。打开后，检查点不可用会阻止受保护操作开始。

`host/history` 提供账户身份隔离入口；`gd-muyu-recovery-v1` 为独立浏览器 IndexedDB，不改服务端历史协议，不要求升级附属插件。不同账号不共用命名空间。它不会随服务器对话跨浏览器同步，也不是加密或防御同源恶意脚本的边界。

容量：每账号最多 64 条、总 2 MiB；单条声明上限 512 KiB，但当前通用 JSON DTO 还有更严格的 32 KiB 字节上限，完整备份与回执重复占用也计入，过大时拒绝开始写入。容量不足拒绝新增，不自动清除不确定记录。GUI 对话底部默认折叠显示，可重新读取及明确删除记录（不会撤销操作），包括其他／已删除暮羽对话的记录，避免遗留记录无法管理。删除父记录会使关联恢复记录无法继续核验，需保留未收口的链路。记录不作为模型上下文，不授予读取当前酒馆资料权限。

## 第二轮：本地核对与重新批准

点击“本地核对并生成剩余预览”仅由本机核对当前宿主数据，不调用模型、不外发资料、不恢复旧授权。全权限模式也不会自动点击这个独立的恢复确认入口。

1. 从当前账号重新读取完整记录，核对父子关系、未被续接标记与原聊天范围。
2. 已完成步骤必须为 `applied_confirmed`，当前定义／值与其预期结果吻合；变量 create 使用完整新定义，update 从原始存储定义仅合并批准差异，保留未修改字段的缺席状态与原始表示，不把规范化默认值当作已写入值。未执行步骤仅接受 `not_started` 或明确的 `not_executed`，原基线及相关依赖必须仍吻合。`applying`、`partial`、`applied_unconfirmed` 或 `outcome_unknown` 步骤不据当前值推断保存成功，需人工核对并重新提出需求。
3. 使用原变量／整单草稿端口生成新的私有 token；普通配置重新验证注册字段契约和差异。旧数据不是草稿，不直接送入 writer。仅剩余步骤进入新预览，尚无任何写入。
4. 用户再次点击“批准并执行这份剩余修改”，复用既有精确动作协调器。先保存子检查点，再 CAS 标记原记录已经交接；CAS 失败不派发。子记录必须与父记录的唯一续接 ID 一致，失败竞争者不能从自己的未执行子记录绕过原锁。
5. 等待落盘后再次复核目标、原完成结果与剩余基线；整单逐步执行，每步前核对原完成结果。取消或切聊天停止未开始步骤，已派发的保存不能伪装成没发生；结果按原协议分别报告。

支持普通无专用副作用配置，以及原整单中已接入的数值变量＋普通配置。不是模型任务、授权等待或脚本运行的断点恢复，也不开放 Shell／代码执行。其他操作重新走原流程。

## 模块边界

- `contract.js`：闭合 DTO 与结果协议校验。
- `intent.js`：完整且有界的纯数据意图与步骤状态；不从回执正文反推。
- `config-undo.js`：普通配置反向预览，完整原字段值与写入后值匹配，不支持缺失字段删除或整仓恢复。
- `journal.js`：脱敏投影、保存与展示快照。
- `workbench.js`：本地核对、新预览、重新批准与续接互斥；复用原有 writer 和动作协调器。
- `indexeddb-store.js`：原子事务、CAS、容量与账号命名空间。
- `actions/coordinator.js`：可选检查点生命周期；只配置／整单装配使用，不拓宽执行权限。
- `host/task-bundle-write.js`：逐步检查点与失败停止，不做跨保存域事务回滚。
- `ui/checkpoint-view.js`：折叠恢复视图、本地核对及新的单独确认按钮，无自动重试。

## 第三轮：普通配置冲突安全撤回

仅开放 v2 普通单份配置操作，要求 `applied_confirmed`、无保存异常／保存后变化警告，并保有完整恢复意图。使用意图中的原基线与请求值构建 before/after，而非解析差异回执。所有原修改字段必须存在原值；缺失字段不赋默认值代替删除。重新验证当前字段与依赖等于原写入后快照，再用原配置合同生成反向预览。

“核对并预览撤回配置”不写入、不调用模型。点击“确认撤回这些配置字段”才通过同一工作台、精确动作协调器和普通配置 writer 执行。保存新的反向操作检查点，CAS 唯一认领原操作，然后再次验证目标、当前值与祖先已完成结果。取消、存储失败、竞争失败或冲突阻止派发。无关字段不回滚；相关字段或依赖已改变，即使意图相似也保守拒绝。原记录保留，`continuedBy` 同时表示已交接给恢复或撤回操作。

撤回是新写入，不保证成功，不是假装原操作从未发生。保存未确认／异常按真实结果记录，不自动重试；在途保存期间的后续修改不被整仓恢复覆盖。未开始的反向操作可按原恢复规则再次核对，未知结果不可直接续跑。新检查点与父记录须保留以证明认领关系；已撤回操作不提供一键重做。

尚未开放整单撤回、变量创建／删除、脚本、资产编辑、记忆裁剪和专用业务副作用的撤回。v1／缺少完整意图的旧操作、持久化未确认的操作不能直接撤回。v2 意图不是完整仓库备份，也不承诺恢复已发生的生成或其他外部效果。

验证：配置真实协调器＋存储重开、真实变量／配置整单、前后写入失败、账号切换、CAS、中文／英文折叠视图。IndexedDB 测试替身只验证事务语义，真实浏览器刷新与配额仍需人工验收。
