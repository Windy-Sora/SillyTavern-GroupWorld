# 按需读取授权

2026-09-25 增量：`providerExecution` 是代码执行审批，不是读取授权。模型必须提供运行时 discover 得到的 Provider ID/版本与用途；控制器按当前聊天、任务和版本核实，UI 仅显示“允许本任务／拒绝”，不会持久批准整类脚本。拒绝、重连与任务结束均清除可执行权；实现版本改变后旧批准不匹配。同一源码版本热重载时仍核对当前实例，丢弃旧实例的迟到结果。历史记录具体的 `source:providerExecution:<id>:<version>` 依赖，不能通过另一个脚本的批准重用旧输出。执行可能有副作用且不能靠超时强制中止。详见 [Provider 执行合同](../modules/providers/EXECUTION.md)。

最新增量：Provider 目录增至11类（另有两类诊断申请）。variables/storyBlueprint 为独立 source-only 聊天来源，旧整包授权不能覆盖；批准其一不批准另一个。目录内容也必须获授权，静态 list 仅描述能力、不返回实际变量名或节点标题。新历史依赖沿用 v5 的 source 值域与任务到期保护。

2026-09-24：统一助手接入九个 Provider 来源及 memoryDiagnostics/directorDiagnostics 的资料级申请。没有发送前整包勾选，没有永久授权或自动批准；写入仍由独立的逐份差异确认处理。

当前规则优先于下文旧分类兼容说明：memoryConfig 为全局来源，持续授权限本连接与当前所有者；其余来源限当前聊天。内部 chat 决定枚举在全局来源表示本连接，不扩大到其他来源。任务授权在任务结束后清除，刷新或重连清除全部授权。

`application/capabilities.js` 集中声明工具依赖：memory.inspect 同时需要 memoryConfig 与 memoryDiagnostics，director.inspect 需要 directorDiagnostics，config.preview 需要 memoryConfig，Provider 读取按来源检查。策略区分缺授权、用户拒绝、无效参数、目标不可用和策略禁止。任一依赖被拒绝就不能换工具绕过；未知来源和不匹配目标均拒绝。模型提出请求不等于获得权限。

统一会话 DTO v5 按实际受保护调用记录 source 依赖，不把所有可用权限记为历史依赖。缺少历史所需权限时自动省略旧历史，续接获齐权限后才恢复；手动省略贯穿所有续接。旧分类会话在新面板只读，下文整包开关与 v3 描述仅供内部兼容。

## 边界与分层

只读工具结果可附加闭合 `hostObservation`，由 application/read-observation.js 基于宿主权限与本次真实决定生成：granted_now、reused 或 denied。它只描述授权经过，不证明读取成功、不批准写入，也不绕过 Broker。全局持续授权说明为 connection，已有授权不猜原始范围。核心运行时仅调用可选观察端口，观察异常不能影响执行结果；附加信息不插入用户消息，不写入会话历史导出。多来源续接保留尚未观察的真实决定，第一次相关读取后消费，之后标为复用。

- `contract.js`：固定来源、闭合申请 Schema、可信标题与响应说明。模型只提供一个 source 和有界 reason，不能指定目标或批准范围。
- `store.js`：连接内的任务授权、聊天授权和拒绝记录，容量有界，不持久化。同步续接失败回滚新决定。
- `read-policy.js`：固定只读来源白名单与个人阅读策略。`all` 直接允许数据读取／草稿预览，不写入批准记录、不批准执行来源；未知来源不放行，明确拒绝仍有效。阅读偏好可持久化，但全权限仍仅本连接有效。历史外发策略独立，资料读取仍受范围与预算限制。
- `application/permissions.js`：与旧 chat/extended/diagnostics 整包开关兼容；旧授权仍有效，不会被按需授权隐式收窄。被整包授权覆盖的细粒度授权不重复列出；撤销整包同时撤销对应细粒度授权。
- `modules/permission`：独立 `muyu.permission.request` 控制工具，普通聊天可用，必须单独调用；不能与读取同批。
- `interactions/store`、应用服务：可信 request/session/task/run/target 身份、一次性消费、失效；重连销毁应用，旧请求无法跨连接复用。
- controller：当前视图与归属检查、授权决定和同步续接协调、历史权限核验。模型文字或澄清回答永远不授予权限。
- Broker：白名单及 Schema 检查后、handler 执行前核验实际权限。`PERMISSION_REQUIRED` 仅用于已知且未被本任务拒绝的来源；硬性拒绝仍为 `PERMISSION_DENIED`。
- 统一助手的只读工具缺权限时，Broker 用静态契约给出 `error.missingSources`（仅来源 ID，不读正文）；运行时暂停原始调用，由宿主逐项生成授权请求。允许后在新执行段重新核验目标和权限，按原工具 ID、版本、参数与 call ID 续接，不要求模型重新选来源或改写参数。拒绝则原调用收到 `PERMISSION_DENIED` 和 `user_denied`，不再请求同一来源。`memoryMaxEntries` 预览额外需要当前聊天的 `memoryDiagnostics`，`configSettings` 不能代替。旧的模型主动请求仍保留兼容；Provider 代码执行必须主动申请专用批准，不进入只读自动续接。
- GUI：展示可信来源、当前模型目的地和模型提供的用途，派发既有请求的 task/chat/deny 决定，不接受模型指定按钮或目标。

## 生命周期

本任务授权仅用于原 task（含澄清/授权续接），终止后清除；此聊天授权仅当前连接和酒馆聊天有效，可跨该聊天内暮羽会话复用。刷新、重连清除全部授权。拒绝后正常续接并禁止本任务重复申请该来源；取消不续接。切换酒馆聊天使待处理申请失效，切换暮羽会话不改变申请归属。

澄清最多三次、资料读取授权申请最多32次、Provider代码执行批准申请最多6次，三类计数独立；由 interactions/limits.js 统一核验，最坏情况下最多42个执行段，不再因一次澄清与五次资料授权而终止。每段仍沿用任务起始预算配置并累计展示开销，等待不计执行超时。达到申请上限时原读取返回 PERMISSION_LIMIT、effectState=not_started，不读取资料；有剩余模型预算时使用已授权证据收尾。应用层再次核验并在异常续接时保留安全错误码。批准后直接续接原工具，不额外调用模型确认，不重做同批已完成工具。取消、切聊天、关闭会话或重连时丢弃待续接状态。

## 历史与摘要

现有 v3 DTO 的 required 闭合值域新增八个 `source:*` 来源，最多十一项；这是资料依赖而非授权，新记录可能不能由旧版读取。旧格式不变，导入仍只读、不能恢复按钮/执行/授权。

保守记录整个会话依赖（包括发送时可用权限），不逐句推断来源。任务授权到期后，下一任务再次发送相关历史或生成摘要必须重新具备权限。可在会话工具选择本次不带历史，或新建对话；省略历史的边界贯穿同任务所有续接，旧摘要也不注入。历史仍可本地查看、导出。已外发数据不可撤回。

统一助手不再因任务授权到期而自动丢弃此前问答。`muyuContextConfig.historyAuthorization` 默认 `auto`：允许发送已有问答及其中引用的资料，包括重连后的当前模型服务；这是持久化的历史外发偏好，不在工具权限仓库内创建任何授权。设置 → 运行预算 → 上下文预算中可选择 `ask`（逐次审批）：资料权限不足时，输入框旁显示历史外发确认，或明确选择本次不带历史。手动确认不会自动发送，未发送草稿保留；仅连接内、指定暮羽会话与当前 ST 目标有效，重连、撤销资料权限会清除，只涵盖确认时已记录的来源。切换策略清除手动历史授权，保存失败保持原策略。旧设置缺少该项时默认为自动允许，但保留原自定义预算；恢复默认上下文预算不改变已保存的外发策略。

历史外发授权与资料读取授权分开：它允许发送已保存对话、整理摘要及在同会话回读已有暮羽消息，不解锁任何新的宿主读取、配置写入或 Provider 执行。导入和归档会话仍只读。任务方案续接核验历史时使用原 taskId，避免忽略已批准的任务来源。

## 验证与限制

权限单测覆盖源/任务/聊天隔离、失败回滚、拒绝、撤销和一次性消费。controller 集成覆盖未授权零读取、跨源拒绝、任务到期历史/摘要保护、拒绝续接、重连、旧请求、混合批次和独立交接额度与达到上限后的安全收尾。GUI 合同测试覆盖中英文、重建与重复点击；不代替浏览器视觉验收。

架构参考本地 Codex 的 request_permissions、请求与批准取交集、原轮次/环境绑定和取消路径；不复制代码，也不引入服务器挂起等待、Guardian 自动审批或沙箱文件权限。实际模型是否恰当申请仍需独立评测。
### 临时授权诊断

授权续接的回滚边界是任务排队：运行准备失败时先取消已排队任务，再撤回授权；运行准备完成后的会话记录同步失败只提示 `HISTORY_SYNC_FAILED`，不能撤回已批准权限而保留可运行任务。该提示不代表会话记录已成功持久化。

重复申请同一来源时，刷新酒馆后在浏览器控制台执行 `globalThis.GD_MUYU_PERMISSION_DEBUG = true`，然后复现。
筛选 `[GD Muyu Permission]`，复制从点击批准到下一次授权申请之间的日志。
日志记录授权提交、任务/聊天授权命中、续接的任务/运行标识、工具策略结果及授权清理；目标只显示页面内的匿名编号，不打印聊天正文、原始聊天标识、授权原因、密钥或请求参数。
默认关闭，最多输出 2000 条；执行 `globalThis.GD_MUYU_PERMISSION_DEBUG = false` 可关闭，刷新也会关闭。
诊断不改变授权结果，不自动授予权限，不上传日志；控制台异常不会阻断业务。
