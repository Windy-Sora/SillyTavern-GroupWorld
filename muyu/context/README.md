# 上下文工作台

当前大窗口实现、容量和未完成边界见 [50 万工作上下文](LARGE-CONTEXT.md)。

## 架构与边界

原始会话与模型上下文是两份不同数据。会话消息不因截取/整理删除；摘要是带来源检查的派生参考资料，不是系统指令、权限、宿主最新事实或任务检查点。

本地 `codex-main/codex-rs/core/src/compact.rs` 与 `context_manager/history.rs` 仅用于学习：借鉴上下文视图与记录分离、独立压缩步骤、来源版本/取消边界。没有复制 Rust 实现、提示词或引入 Codex 服务依赖。暮羽不实施运行中压缩。

| 文件/层 | 职责 |
| --- | --- |
| `policy.js` | 闭合配置、JSON 字节统计、保守 Token 估算和安全投影 |
| `planner.js` | 完整问答选取、摘要来源检查、连续分段整理候选 |
| `compaction.js` | 无工具摘要请求与有界响应解析，不拥有存储或权限 |
| `summary-contract.js` | 接收/存档共用的摘要字节边界与不可信参考包装 |
| `auto-compaction.js` | 完整请求压力判定与按会话/范围隔离的内存熔断计数 |
| `composition.js` / `core/runtime.js` | 组合层注入上下文端口；内核仍只导入 core 文件，负责同一调用/时间预算、每请求检查、取消和物理 drain |
| `model/chat-completions.js` | 统计最终适配后的 payload，包含实际工具定义及私有思考回传；网络前再守卫 |
| `application/controller.js` | 会话归属、授权、发送时快照、手动整理、摘要写回 |
| `modules/history/` | 当前暮羽会话原文的有界关键词搜索、索引与指纹核验回读；不拥有授权 |
| `sessions/` | v3 可选摘要随原始记录一起保存，摘要不进入索引 |
| `ui/context-view.js` | 配置、估算/实测区分、查看/清除摘要、整理确认 |

## 设置与用户入口

行为偏好：正式请求的系统指令纳入估算和字节总量，单列 instructionBytes；不能被历史裁剪删除。摘要请求不携带行为偏好，具体见 [指令合同](../instructions/README.md)。

齿轮 → 上下文预算。插件设置 `muyuContextConfig` 排除在剧情配置档之外。

- `inputTokens`：新安装默认 `900000`（本地估算 Token），面向 1M 模型保留输出与估算余量，但不保证一定符合服务商窗口。未标记的旧完整默认组合（32000或500000、recentTurns=12、autoSummary=false）读取时升级；其他组合及 `null` 保留。明确保存后写入 `muyuContextBudgetVersion`，即便设置成旧默认值也不再升级；历史上与默认完全相同的手动设置无法区分。可选 `null` 不按估算 Token 拦截，仅受 8 MiB 请求体安全上限保护。手动模式支持 4096–1000000，估算不是实际模型窗口；小模型需降低预算，增大预算可能增加费用。
- `recentTurns`：1–24，默认 12。只作为全部原文已能放入近期保留额度的短对话整理参考值；长对话按预算决定近期原文，不受两轮或此参考值封顶。不限制正常请求的历史轮数，也不单独触发整理。
- `autoSummary`：默认关闭。新任务首次请求前，旧历史未覆盖，或适配器计量后的完整请求达到输入/请求体预算的 80% 时尝试；打开面板/浏览历史不调用模型。预算紧张无法保留正式回答调用时不整理。80% 为本地压力策略，不是服务商模型窗口或实际 Token 承诺。
- `summaryTokens`：摘要输出上限，1024–32768，默认 16384；旧配置缺少此字段时补默认值，不写回或改变已有自定义输入预算。已明确保存的额度保持不变；未标记、可识别的旧整套默认组合可升级。实际调用还受本轮单次输出预算限制。位于“上下文预算 → 摘要输出预算（Token）”。

聊天区“上下文”提供计划携带轮数、未覆盖消息数、历史部分估算、最后一次请求计量及摘要查看。计划不是最终请求；适配器检查仍可能减少旧历史，实际保留条数单独显示。运行中修改设置只影响下一次发送。

“本次不携带旧历史”只跳过旧对话和摘要，不删除原文、不撤销工具授权；成功入队后自动复位，不与已有配置草稿续改组合。手动“立即整理历史”须再次确认外发，沿用已有连接和相关资料授权。

## 输入计量和裁剪

无新增 tokenizer 依赖。Token 估算使用序列化 UTF-8 字节数 / 2 向上取整，是偏保守的启发式，不能保证等于任何模型实际分词。输入预算与最大 8 MiB 请求字节保护并用。

历史规划上限为 min(输入预算或请求字节上限/2, 请求字节上限/2) 的 90%，预留 10% 给当前问题、指令、工具及后续结果；不是模型真实余量。预算内按完整成功问答尽量保留全部原文，不按固定轮数截断。模型第一次正式调用前，无有效摘要时可继续移除完整旧问答；有效摘要及其连续原文尾部不裁剪，放不下以 `CONTEXT_INCOMPLETE` 停止。当前问题、任务约束和本轮工具调用不裁剪，其他输入超限以 `CONTEXT_LIMIT` 停止，绝不破坏工具配对或移动私有思考缓存索引。

消息、工具定义、工具结果、思考回传字节是序列化分项，存在包含关系，不能相加当总量。服务商报告的实际输入/输出 Token 仍见本轮开销；缺失报告显示未知，不当作零，也不从字节数伪造实测。摘要调用的实际用量可单独查看，并包含在总量内。

## 整理规则

摘要与恢复指令区分三类信息：用户明确要求/接受且尚未完成的目标、助手可选建议或当前目标所需实现步骤、未知信息与条件阻塞。可获得时记录简短用户原话及 sourceIndex；继承旧摘要的内容不得虚构原文依据。最新取消、拒绝、完成与收窄范围优先，简短同意仅承接明确指向的建议；滚动摘要不得把未接受建议或未知信息逐渐升级为用户待办。这是模型行为引导，不是确定性语义校验，不新增任务存储或改变摘要/存档格式。

每次最多整理一个连续历史段；按估算 Token 限制的模式下，候选请求不超过输入预算的 98%；仅请求体保护模式下不超过请求体安全上限的 98%。近期原文目标额度为 min(输入预算或请求体字节上限/2, 请求体字节上限/2) 的 10%，默认约 90000 估算 Token；按完整问答从后向前保留连续原文，序列化字节计量包含中间及末尾的失败/取消消息、JSON 转义和 Unicode。全部未覆盖原文都能放入此额度时，使用 recentTurns 参考值，至少留一轮作为摘要候选；最近一轮超出额度时允许整轮转入摘要，绝不切断问答。没有新增配置或存档字段。

有有效旧摘要时，合并旧摘要与下一段完整问答，来源指纹仍覆盖原始记录的整个前缀。不会因为旧摘要加全部尾部放不下而无条件把最新问答也列为摘要目标。单条超长消息会分段传给摘要模型（普通模型文本上限为 2 MiB 序列化 UTF-8，工作消息上限 4096，历史规划预留 256 个消息槽位给本轮轨迹），但候选超出上述上限时不会跳过前缀；一次整理不保证覆盖全部旧历史。近期额度是规划目标，不是强制裁剪尾部：受单次摘要请求限制时实际未覆盖尾部可能更大，仍须完整携带，放不下就阻塞。滚动摘要可能损失细节，原文始终可查看/导出。

摘要调用无工具，按任务交接结构保留最新目标/修正、带来源的事实、操作结果与保存确认、待办、偏好及不确定信息，不再要求 1500 字符。讨论主题/背景不自动成为待办。请求使用独立 `reasoning: 'disabled'`：DeepSeek 适配器明确关闭思考并省略 reasoning_effort；通用兼容接口不发送专有字段，不保证其服务端实际关闭推理。正常 Agent 思考与私有工具回传不变。手动输出上限为 min(summaryTokens, 本轮单次输出上限)；自动初次为 min(16384, summaryTokens, 本轮单次输出上限)。仅在输出截断、尚有调用/时间预算且可提高输出上限时自动重试一次，使用配置摘要上限与本轮输出上限的较小值，使用新的私有模型上下文，至少预留一次正式回答调用。两次共用整理子步骤截止时间，手动整理不重试。默认额度已用满时不重复同额度调用，不接纳半截摘要。不会回放旧工具调用或隐藏思考。

接收与存档共同限制摘要文本的 JSON 序列化 UTF-8 字节为 512 KiB（含字符串引号与转义），不是目标长度或 Token 换算；工作缓冲另以 UTF-16 长度有界，完整响应后精确校验。摘要连同参考包装的序列化字节必须严格小于被替换历史，否则 `SUMMARY_NOT_SMALLER`；超安全上限为 `SUMMARY_TOO_LARGE`。两者均不提交、不截取字符串伪装成功，保留原文与旧摘要，自动整理仍遵循原有回退/连续性保护。不接纳工具请求或未完成响应。记录结构不变，新客户端可读取旧短摘要；旧版客户端可能拒绝超 6000 字符的新摘要，不应混用旧版客户端进行存档改写。

完整请求压力包含问题、运行指令、工具定义、回执上下文和适配器私有开销；不只统计历史。压力检查仅在新任务首次请求前进行，按需生成有界摘要候选，不在低压力时重复扫描整个摘要前缀，不在授权续接或运行中重写工具/思考轨迹。20% 输入余量用于后续增长；现有默认输入预算另为输出留余量，但未发现真实模型窗口，不能据此保证输入+输出一定可容纳。首次高压力整理失败、被预算跳过或无有效候选时，若完整请求仍超硬上限则停止，不能裁掉该历史强行发送；仍能完整容纳时可按原文继续。

自动整理按会话 ID 与存档范围累计连续失败，单轮的截断重试只计一次；取消不计失败，摘要成功写回会清零（即使后续完整请求仍因容量不足停止，也算已取得进展），后续正常回答成功但摘要失败不会清零。三轮失败后暂停自动整理：完整请求能容纳则继续原文，超预算时停止；未覆盖的旧摘要尾部仍遵循原连续性保护。GUI 在“上下文”显示说明和“重新允许自动整理”。手动整理成功、明确恢复、实际改变运行/上下文预算或重连可恢复，撤权也会清空状态；旧配置下的在途结果不能重新记入新计数。状态仅在内存，不保存文本、权限或存档字段，不为恢复提供任何新授权。

使用有效摘要时，必须携带其覆盖前缀之后的全部原文，不受 recentTurns 窗口裁断；来源覆盖与原文尾部之间不得有缺口。无法完整携带时标记阻塞；整理失败或因预算跳过时以 `CONTEXT_INCOMPLETE` 停止，不能发送旧摘要加不连续近况。成功的部分整理也保留完整剩余尾部，最终请求计量不得再次裁剪这份受保护历史。可以继续手动整理、增加预算，或由用户明确选择本次不携带历史；原始会话记录始终保留。

覆盖状态：规划器提供闭合计数 `total/summarized/raw/omitted/excluded` 与 `complete/window/blocked/omitted` 状态，所有分类合计必须等于原始消息数。`summarized` 表示摘要来源覆盖的原文条数，不是摘要质量保证；`excluded` 单独表示授权或用户主动排除，不能当成预算缺口。运行记录只投影计数和 planned/skipped/summarized/fallback/blocked 状态，不存正文、来源指纹、密钥或任意错误文本。界面分开显示当前发送计划与最近任务的恢复/阻塞结果，不自动增加预算或勾选不携带历史。

摘要候选以完整问答作为结束边界，但连续前缀内夹有失败/取消的原始消息时也必须携带，不能把未读原文算入摘要覆盖范围。授权等待后的在途工具续接不重新整理历史，不改变已有工具配对或私有思考索引；仅新任务可按当前设置重新规划。没有新增存储字段或数据库迁移。

- 压缩时间预算 `summaryTimeMs` 默认 300 秒，可在上下文设置中配置 10–1800 秒；旧配置缺失该字段时补齐，不改其他自定义参数。
- 自动整理计入本轮模型调用数与总超时；调用预算小于 3 或剩余时间不超过 10 秒时跳过。实际期限取压缩预算与本轮剩余时间减 10 秒的较小值，给后续回答保留时间。默认本轮 300 秒时，自动压缩最多约 290 秒；一次截断重试共用原截止时间，不重新计时。
- 手动整理是单独任务：最多一次模型调用，时间取压缩预算与单轮超时的较小值（两者默认均为 300 秒），无工具，也不生成伪造用户/助手消息。保存新预算不延长在途运行；取消、超时、物理清理和迟到摘要拒绝仍沿用原边界。
- 普通模型/解析失败：原文和旧摘要不变；存在旧摘要时只能回退到旧摘要加完整未覆盖原文，放不下则停止。没有有效摘要时保持原有近期完整问答窗口；无无限重试。摘要用量展示实际调用次数及已报告 Token 合计，缺失报告不伪造成零。
- 取消、超时：不再发起后续请求；等待物理 drain 后才能释放运行槽。部分流、迟到结果不提交摘要。
- 写回检查原会话、当前聊天/全局范围、相关授权及来源指纹。重命名不改变摘要来源；切聊天、删除、撤权不能让迟到结果污染会话。

## 摘要之外的原文按需检索

暮羽可使用 `muyu.history.search` 按关键词定位当前助手会话的旧原文，再用 `muyu.history.read` 根据返回的位置和指纹读取上下文。每次搜索有消息数、扫描字符数、命中数和摘录长度限制；完整检索需沿游标继续，空的部分页不证明内容不存在。结果与 list/read 共用历史读取额度，授权／澄清续接不会重置已用计数。仅检索本任务允许的历史快照，不扩大到其他存档或酒馆聊天，不绕过主动历史排除和撤权。详细参数与边界见 [历史模块合同](../modules/history/README.md)。

本能力用于找回摘要可能遗漏的细节，不是语义检索或答案正确性保证；关键词命中须核对用户后续更正，历史记录也不能证明当前宿主值。没有增加依赖、存档字段、额外 GUI 授权开关或常驻全文注入。

## 存储与兼容

摘要从会话 DTO v3 起提供兼容字段；当前会话与后端版本以 [会话合同](../sessions/README.md) 为准。旧记录读取时补 contextSummary，不通过较旧客户端降级覆盖新格式。

摘要字段固定为 `through`、`fingerprint`、`text`、`createdAt`。fingerprint 是非加密变更检测，不是签名或授权依据；摘要本身始终不可信。消息变更导致来源不匹配时不使用摘要，界面标注失效。

摘要保存/清除沿用会话自动保存开关：关闭时只改本页工作副本，不暗中落盘；若磁盘已有旧版本，刷新可能重新读到它。JSON 导出包含摘要和原文，Markdown 保留原始问答。导入生成新只读记录，摘要不能解锁执行。授权从不随摘要持久化。

## 范围核验与验证

手动整理在调用模型前核验当前酒馆聊天与所选会话归属；切聊天而尚未在新聊天发送时，须回原聊天或先发送新消息明确重新绑定。会话仍可跨聊天续聊。存档容量预留和恢复备份见 [会话合同](../sessions/README.md)，与模型输入预算相互独立。

手动与自动摘要写回沿用已有对话外发策略，不要求已结束任务的资料读取授权仍有效，也不授予重新读取、配置写入或代码执行。写回继续校验来源指纹、会话范围与只读状态；撤权、重连或外发策略变化使在途摘要失效。

候选规划按新增分段累计字节与消息数，保持连续前缀、原始编号及 Unicode 边界，避免反复序列化整个增长前缀。

回归应覆盖计量、连续覆盖、失败／取消、在途续接、摘要落盘及失效、熔断、原文检索、预算变更和 GUI 草稿。历史测试数量与实测记录见 [TESTING.md](../../docs/TESTING.md)；合成数据性能不代表真实浏览器或模型摘要质量。
