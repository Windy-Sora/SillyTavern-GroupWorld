# 会话仓库与历史工作台

## 读取来源与写入位置（当前）

齿轮 → 存储与记忆 → 对话历史提供“读取历史来源”单选和“写入位置（可多选）”：当前浏览器、酒馆账户设置、酒馆世界书、服务插件私有文件。`muyuHistoryReadSource` / `muyuHistoryWriteTargets` 为新偏好；null 兼容旧 `muyuHistoryStorage` / `muyuHistoryAccountStorage`。旧自动偏好初次连接仍服务端优先、插件缺席才选择浏览器，本端口解析来源后不再悄悄切换；修改任一新选项后持久化明确的读取源与写入列表。旧开关不会默认变成全部写入，新偏好不通过剧情配置档分享或导入。

自动模式仍优先使用服务插件私有文件，插件缺席时使用浏览器 IndexedDB。世界书模式无需服务插件，可在同一酒馆账号下跨浏览器/设备接续，内部存档合同见下文。账户设置模式使用本体 `settings-store.js`，不探测服务插件、不依赖 IndexedDB；`muyuHistoryData` 随 GD 的 `extension_settings` 通过酒馆设置接口保存，通常位于当前账户 settings.json。同一账号换浏览器可读取；这些方式都不代表跨酒馆服务器同步，也不写入 RP 聊天存档或角色卡。

`muyuHistoryEnabled` 仍独立控制自动保存。关闭自动保存或某位置写入均不关闭读取、不删除数据。打开写入只影响之后的保存，不批量搬迁旧历史；列表不拼接其他来源，明确选择的来源失效不回退。旧的“打开服务端时自动复制浏览器历史”已移除，保留原件并使用显式复制或只读导入。

自动保存开关先确认偏好，再连接存储；连接失败仍保留开启选择，不冒充落盘。切换读取源只在空闲且无待授权时进行：先完成旧队列，预检目标，再确认设置，卸载旧运行态后使用另一份来源绑定仓库。每个来源保留各自的本页记录、草稿和滚动，同 ID 不混用；连接或设置保存失败留在原来源，切换期间更换聊天会拒绝过时结果。当前读取源及各位置上次保存结果分别展示。

### 多位置保存合同

`routed-store.js` 组合一个 reader 与多个惰性打开的 writer，不修改会话 DTO 或服务插件协议。每个目标分别维护确认 revision 与完整规范化内容的 SHA-256 指纹（仅忽略各库 revision）。新目标只有不存在、已等于待保存记录，或等于本次读取基线时才能创建/更新；已确认目标再次保存须匹配自己的基线。关掉再开启不会绕过外部编辑/删除。世界书仍无跨设备 CAS，此层不能弥补宿主并发限制。

分别报告 saved / failed / disabled，部分失败保留工作副本，不宣称整体成功，不回滚已完成位置。新内容仍可送往正常目标；显式重试对相同内容只核验，不重复写。某处容量不足不替其他位置决定上限；单一带容量预检的后端仍沿用原预检。源已落盘但回包丢失时，刷新/重试仅在完整内容一致后确认自身结果。未写读取源时 reader revision 不前进，界面明确“当前读取位置未更新”，不拿其他库的版本冒充 reader 版本。

列表与历史来自 reader；保存前可读取各目标同 ID 记录作防覆盖核验，但不混入历史、不因此外发模型。手动重命名、归档、删除只作用当前读取源，且要求该源写入开启；不广播删除备份。显式复制也要求目标写入开启。偏好变更先等待当前写入，不在半次保存中改策略。授权、任务和独立 IndexedDB 检查点不随备份/切库恢复。

账户设置记录仍使用现有版本化会话 DTO：正文、摘要、回执与来源依赖，不保存密钥、工具执行轨迹或授权凭据；刷新不恢复任务执行或资料权限。独立账户 namespace 和访问前后身份检查保持不变，未知版本或损坏数据拒绝读取，不静默清空。

该后端最多64个会话、单条8 MiB、整个存储 JSON 32 MiB（UTF-8），低于独立存储上限；超限拒绝新写入，不裁剪旧消息。失败保留本页工作副本，允许重试或导出；回滚只处理本次存储字段，不覆盖并发替换和其他设置。读取等待当前页面的存储写入结束，局部 revision 检查与同一设置对象的写入队列避免本页互相覆盖。

**限制：酒馆设置是整份文档保存，不提供跨标签页/设备的原子版本比较。** 本页 revision 检查不能保证多标签页一致性；其他标签页保存旧设置可能覆盖对话。应尽量单标签页使用并定期导出。保存错误也不能断言服务端未落盘。所有内容为明文，设置备份会包含私人对话；配置档快照、JSON/ZIP 导出、导入与应用均排除 `muyuHistoryData` 和存储偏好，不通过剧情配置档分享私人记录。

## 统一助手记录（当前）

### 存储四轮收口与验收边界

第一轮外部更新/删除与显式重载、第二轮单 reader/多 writer、第三轮只读导入去重、第四轮交叉回归均已实现。`tests/unit/muyu-history-storage-lifecycle.test.mjs` 使用生产 `createHistoryPort`、账户设置后端和世界书 HTTP/编解码适配；HTTP 响应为合成宿主，浏览器与服务端传输为内存替身。它不是实际 ST、IndexedDB 或文件服务的端到端测试，真实后端分别还有专门套件。

| 交叉场景 | 验证的结果 |
| --- | --- |
| 四处保存后，从四个来源分别重开、重复导入 | 各来源只读自己的列表；同内容复用已保存备份 |
| 关闭全部写入后，导入修改过的备份并重开 | 新版本只留本页，不覆盖旧版本，不冒充已保存 |

| 账户设置保存失败后重试 | 设置字段回滚，健康副本保留且不重复写 |

开启写入位置本身不回填已经干净的记录；它影响后续保存。要复制旧库，请使用显式复制入口，不要把“重试”理解成全库搬迁。

人工验收仍待完成：同一账户电脑与手机依次接续（不要同时编辑）、手机输入/授权期间切库按钮禁用、切库后草稿和滚动恢复、断网恢复、世界书管理器中说明/删除警告是否显眼，以及实际安装/未安装服务插件两种环境。浏览器数据只在当前浏览器可用；其他后端仅在同一 ST 服务器/账户下共享。确定性测试不承诺跨设备 CAS、跨设备并发唯一导入、物理删书后的恢复或端到端持久化。

### 只读备份导入去重（第三轮）

导入先等待保存队列，重新读取当前 reader 的目录，只对该来源的只读备份及本页未保存导入副本做内容核对；不扫描其他写入位置，不把导入当成可运行原对话。相同内容返回已有只读记录（含已归档版本），不新增、不重写、不取消归档；内容变化生成新 UUID 的独立只读版本，保留旧版本。界面分别显示“相同已存在”和“新增只读备份”，新增不等于持久化成功，仍以各位置保存状态为准。

`exchange.js` 的 SHA-256 指纹比较规范化后的标题、归属、消息顺序/正文、摘要、回执与范围切换。忽略导入会重写的 ID、revision、创建/更新时间及本地归档/导入标记；running 与 importedRecord 的 interrupted 映射一致，来源依赖按同一保守导入规则计算。对象字段顺序无关，数组顺序保留。指纹只作本地去重，不是认证或授权；不增加 DTO 字段、持久索引或服务协议。旧版备份及导入副本再导出仍可识别，不按原 ID、时间新旧或消息数猜相同。

目录前后核对、现读正文与本页冲突检查防止拿旧缓存跳过或覆盖外部改动；来源失败/损坏不当空库，原记录保留，导入可重试。自动保存关闭仍核对所选读取源，新版本仅留本页；容量满时仍能识别重复，新版本照常受容量限制。同一页面不并发导入；跨设备同时导入仍受原后端并发能力限制，不承诺全局唯一去重。导入不恢复授权、工具执行、待审批任务或检查点；不自动清理以前已经存在的重复记录。

新 assistant 会话使用 DTO v5，跨 ST 聊天续聊后升为 v6 并保留最近最多 32 次范围切换的元数据；记录新问题后升为 v7，用 user 消息的 origin 区分原始问题与任务续接，避免恢复授权标签或澄清短答。物理 IndexedDB 仍为 v3，不清库。v1–v6 保持可读，新格式不保证旧代码可读；旧记录缺少来源时保守隐藏无法判断的失败恢复入口。回执保留 v4 的事实结构，v5 起使用 source:memoryConfig 依赖。

统一入口隐藏任务筛选；旧分类会话可查看、导出，但不能直接续接为统一助手。导入仍只读，不恢复权限、工具调用或审批。新会话按实际受保护工具调用记录来源依赖。任务授权到期后自动省略未获授权的历史，并告知模型需申请的来源；同一任务续接获齐权限后才可重新带入。用户主动选择不带历史时，所有续接都尊重该选择。

## 分层与数据

- `contract.js`：v2 闭合 DTO、v1 读取升级、容量、归属键、摘要及有界历史选择。
- `library.js`：工作副本、惰性读取、保存队列与失败状态；不依赖 DOM、模型或 ST。
- `memory-store.js`：隔离内存存储端口，供测试等场景使用。
- `indexeddb-store.js`：浏览器回退存储；沿用数据库名 `gd-muyu-history-v1`，records/summaries 两个 store，主键为账户 namespace＋会话 UUID。摘要和正文在同一事务写入/删除，使用 revision 比较，不静默覆盖其他标签页。
- `server-store.js` 与 `../server-plugin/index.cjs`：可选 ST 服务端插件，在已认证用户的私有数据根目录写入独立 JSON 文件，不使用扩展静态目录。旧自动偏好初次连接时可选择服务端，显式选择服务端后缺席或网络失败均报错，不切库；不再自动复制浏览器记录。
- `exchange.js`：有界导入预览、新 ID 的只读副本、JSON/Markdown 导出；不执行文件中的内容。
- `host/history.js`：宿主账户适配和插件保存开关；`ui/history-view.js` 提供侧栏与筛选，`ui/history-actions.js` 提供确认表单和文件交换。

会话记录包含版本、UUID、revision、任务/聊天归属、标题、时间、用户/最终助手消息、末次状态、继续对话所需的数据类别，以及 archived/imported 标记。`required` 是历史数据的外发前置条件，不是授权凭据。消息 runId 仅用于配对与展示，不能恢复执行权。

v1 在读取时补齐两个 false 标记，下一次确认写入时保存为 v2；不清库迁移，未知未来版本拒绝修改。IDB 版本升级会关闭配合 versionchange 的旧连接；旧代码的 version=1 重新打开请求会失败，需要刷新旧标签页，避免旧写入逻辑参与新管理流程。

不保存连接密钥、endpoint、思考、工具参数/正文、内部错误或可执行产物；用户输入和助手最终回答本身可能包含敏感内容。历史不是加密保险箱，不对抗同源恶意脚本。

## 世界书存储（已接入选择器与显式复制）

`worldbook-contract.js`、`worldbook-store.js` 与 `../host/worldbook-history.js` 提供独立后端及 ST 原生 HTTP 适配，已通过读写调度与 GUI 接入。旧初始偏好保留；只有明确开启世界书写入并保存会话或显式复制时才创建内部书。选择世界书阅读、打开空列表不会创建书，不依赖服务插件或对话 IndexedDB；操作恢复检查点仍独立依赖 IndexedDB。

- 新会话通过 `worldbook-volume.js` 合并到当前账户的 `GD-Muyu-History-v2-<namespace>-00000000-0000-0000-0000-000000000001` 主卷，后续分卷依次使用尾号2、3等（最多1024卷，活跃会话与正文总配额不变）。每份会话保留独立 v1 信封、版本、校验及删除标记。整卷条目均禁用、无关键词、非常驻、禁止递归；主说明明确整本删除会影响卷内所有会话。适配层向原有仓库提供独立会话视图，读写会校验各卷，列表也读取卷内正文，不承诺纯元数据读取。
- 齿轮 → 存储与记忆 → 对话历史 → 世界书分卷设置：`muyuHistoryVolumeMiB` 默认8，整数1–16 MiB，修改自动保存，当前打开的后端下次新会话分配直接读取，不需刷新。按整本序列化UTF-8字节（含说明、目录与转义）计算，优先复用可容纳的新会话位置，无合适卷再新建；单会话超目标时可独占一卷。目标只控制新会话分配，调小不搬迁旧数据，读取不受新阈值限制；已有会话仍原卷更新，整卷增长超过20 MiB硬上限时拒绝保存并保留本页内容，不截断。已有会话的跨卷迁移/整理尚未提供，不能把此设置描述为严格容量封顶或自动整理。
- 未合并的旧 `GD-Muyu-History-v1-<namespace>-<id>` 单会话书仍原地读取和更新；不会自动复制或删除。显式合并后以新卷为主，v2目录行的可选`legacyHash`保存原v1信封JSON的SHA-256，旧书仍存在时须验证完整格式和指纹；它是静态备份，不随新卷更新或删除同步。不同卷同ID或无合并凭据的新旧重复仍拒绝选择，不任意取一份覆盖。存储阈值不进入剧情配置档的快照、应用、JSON/ZIP导出或导入。
- 第一条以“暮羽对话存档说明与删除警告 / READ FIRST”标明用途，中英文说明它不是剧情资料、无需启用绑定、明文隐私、禁止手工编辑、跨设备并发限制、删书/删条目导致历史丢失或不可读，以及不能撤销操作或清除其他副本。删除标记使用单独说明，提醒物理删书会移除防复活保护。旧版精确说明与条目标题仍可读取，下次正常写入采用新文案，不为更新说明批量改写旧书。
- 名称只用于定位，不能证明归属。读取正文、替换和删除还须通过格式版本、namespace、会话 ID、摘要、完整条目结构、正文 SHA-256 和 revision 校验。摘要与正文只保存现有会话 DTO，不恢复权限、业务任务或可执行对象。哈希用于损坏检测，不是认证或加密。
- 宿主通过 `/api/worldinfo/list`、`get`、`edit` 读取和保存。每次请求前后检查注入的账户身份守卫；HTTP 错误、异常回包、超时均失败。保存后直接向服务端回读核验，绕过 `loadWorldInfo` 缓存；失败保留上层会话工作副本，不切换存储、不补偿覆盖。
- 同一次保存回执丢失后，只有服务端已存的下一 revision 与本次完整记录完全一致时，重试才能直接确认成功。内容不同则冲突。删除写入不含标题或正文的 tombstone，保留 revision，阻止旧页面 create/update 复活。物理删除内部书会移除这项保护，因此后续 GUI 不应把物理删书作为普通删对话的实现。
- 本页队列串行化同 namespace 的修改；支持 Web Locks 时额外协调同源标签页，局域网 HTTP 不支持时仍可运行。ST 接口没有服务端 CAS，写前版本检查与写后回读不能保证跨设备同时编辑安全。第一版面向跨设备接续，不能宣称与私有服务端后端等价的并发保证。
- 单会话正文最多 8 MiB、活跃正文合计 64 MiB、最多 64 个活跃会话；单书序列化最多 20 MiB，数据块最多 128 条、每块 65536 字符。删除标记不占活跃会话名额，保留在目录中。存档空间预检包括本页尚未保存的工作副本和最大回答预留；不是跨设备配额预订。
- 测试通过模拟 ST 原生 HTTP 与真实会话管理层验证失败保留、回读、重试、冲突、删除防复活、账号切换、Unicode 分块及容量。尚未进行目标酒馆的真实跨设备验收。

`systems/internal-world-books.js` 统一分类内部名称；正常世界书概况、正文、搜索、编辑/绑定、GD 手动选择、扫描器及选择列表先排除内部名称再计算限额和序号。读取到改名存档的格式标记时，正文/编辑/扫描路径仍拒绝使用；这只是隔离分类，不是写权限或真实性证明。导演拿到带来源书名的激活条目时再次排除内部书，不在过滤成空后回退到同一批未过滤拼接文本。用户 Provider/脚本或其他同源插件仍可自行直接读文件，此隔离不构成页面代码的安全边界。

历史列表始终使用原生 `/list`，正文和保存核验使用直接 `/get`；不依赖或改写酒馆前端世界书缓存，不调用会切换编辑器的列表刷新。用户打开酒馆原生世界书管理时可能需要刷新列表。GUI 分别展示实际读取位置与各写入状态，中英文提示容量、明文保存和跨设备并发限制。JSON 导入仍按独立新 ID 的只读备份合同处理，不能当作自动迁移；重复导入去重留待下一轮。

### 显式合并旧版世界书与独立清理

选中世界书为读取源并开启该源写入后，齿轮 → 存储与记忆 → 对话历史 → 合并旧版世界书存档：先导出备份、关闭其他设备和旧页面，再点“确认合并（保留旧书）”。仅处理同账户的v1专用书，连同删除标记一起迁入按当前容量目标分配的v2卷；保留ID、正文和revision，不复活删除记录，不重新导入为新会话。未保存/失败的本页工作副本存在时拒绝处理，不丢弃草稿，不恢复授权、任务或操作检查点。

合并在原namespace队列及可用的Web Lock内串行执行，与普通保存共用容量分配及整卷前后核验。每份源书完整验证并复读，写入新卷时同时保存旧副本指纹，因此落盘后回包丢失仍可读取新卷，重试只核验并跳过已合并项。合并中断保留旧书、已完成卷与本页记录；不自动续跑或补偿覆盖。保留旧书不意味着将两份内容混合：旧副本无改动时只返回新卷；旧书被外部修改后报冲突，不自动选较新版本，也不覆盖或清理分叉。

“清理已合并的旧书…”是独立操作，需再点“确认清理旧书（不可撤销）”。只允许物理删除已合并且与记录指纹相同的旧v1书，删除前后核验目标新卷及源状态；未合并、分叉、损坏、普通世界书及其他账户/来源均不删除。清理不删除新卷、当前会话或卷内删除标记；若保存/删除回执丢失则报告未确认并停止，重试重新扫描，不盲目再次删除。旧页面可能重建旧书，因此必须先关闭；没有跨设备CAS，不能保证其他设备并发写入时的原子迁移或清理。清理确认绑定当前存储来源，切库、关闭写入、开始任务或卸载面板后不能沿用旧确认。

结果区分别显示合并、已合并跳过、已清理、冲突或未合并跳过、未确认与错误。默认合并不会减少原生世界书列表中的旧书数量；另行确认清理才移除这些旧备份。保留的旧副本可能含已在新卷删除的旧正文，不应把新卷删除等同于清除全部备份。操作仅使用ST原生`/list`、`/get`、`/edit`和清理时的`/delete`，不依赖服务插件；原生世界书面板可能需手动刷新列表。

### 显式复制旧历史

实际后端已切换为世界书后，“复制旧历史到世界书…”提供当前浏览器、酒馆账户设置和服务插件私有文件三个明确来源。展开说明后点击“确认复制到世界书（保留原件）”才执行；仅列出并读取所选旧库，不自动探测替代来源。服务插件不存在时明确失败，不回退到浏览器。先导出备份、停止其他设备编辑；自动保存关闭时可先刷新历史连接后端。有未保存工作副本时拒绝复制，先重试保存或导出处理。

`copy-history.js` 只依赖存储端口，逐条校验现有 DTO、ID、范围和目录 revision，创建前复读源记录检查变化。复制保留会话 ID、归属、正文、摘要、历史回执与依赖；目标 revision 从 1 开始，不恢复授权、执行、检查点或本页输入草稿。相同 ID 且完整内容相同（仅忽略存储 revision）跳过，不同内容、源变化或目标 tombstone 记冲突，绝不 update/remove、不合并、不分配新 ID 绕过删除标记。

容量、版本、身份或网络异常停止后续复制，保留原件和已完成部分；结果分开报告确认复制、相同跳过、冲突跳过与未确认条数。保存回包丢失不计成功，重试若读到相同完整记录则记相同跳过。每次重试重新检查源与目标，不持久化迁移任务、不后台续跑。完成后刷新目标摘要，不替换已加载工作副本或当前输入。与普通世界书保存一样没有跨设备 CAS；源复读也不是跨设备事务，应避免同时在两处继续同一会话。

## 账户与聊天归属

组合层按需读取本地 ST `scripts/user.js` 导出的账户状态。多账户要求明确的 `accountsEnabled=true`、非空 handle 和创建时间；单账户必须明确 `accountsEnabled=false`。缺失接口、身份或 Web Crypto 时拒绝持久化，不用默认用户兜底。

稳定 namespace 由账户类型/handle/创建时间的 SHA-256 前 128 位生成，避免各标签页首次生成不同随机编号；浏览器 IndexedDB 自带 origin 隔离。摘要减少磁盘中的原始账户标识，但不是密码学访问控制。账户重建、服务迁移或更换 origin 不自动迁移历史；不承诺跨设备同步。存储访问前检查账户，读取返回后再次检查。

运行权限仍使用页面级身份；持久归属使用任务＋群组 ID/角色头像标识＋chatId，不持久化页面随机 ID。仅查看历史不会改变归属，也不会替用户切换 ST 聊天；统一助手在用户主动于新聊天继续发送后，才把记录的当前归属改为新聊天。下一轮模型获得切换提示；旧聊天授权、运行任务和产物不会随记录迁移。

## 保存与恢复

### 刷新与外部版本变化（读写分离第一轮）

存储端口提供当前账户 namespace 与实际后端组成的固定 `sourceKey`；每份仓库连接后锁定该来源，变化时拒绝读写，不把新来源混入旧缓存。输入、滚动与历史外发许可缓存有独立生命周期前缀；切库使用另一份来源绑定仓库，而不是修改旧仓库的来源。

刷新以及重新开启自动保存时，将已加载记录的最后确认存储摘要与新目录比较。不同版本标记 `changed`，原本已保存而现在不存在的标记 `deleted`；保留本页记录、未保存正文与未发送文字，侧栏和当前会话显示变化，暂停该记录的继续发送和自动保存，不把工作副本悄悄覆盖成外部版本。未加载记录仍只刷新摘要，不全库读取正文。只有来源按现有存储契约更新目录/revision 时才能据此检测变化，不承诺识别绕过存储契约的任意手工篡改。

用户可以在会话提示中点击“重新载入存储版本…”，先导出所需内容，再明确确认放弃本页记录修改。新正文和新目录核对成功后，先卸载旧 runtime、产物及相关回调关联，再替换记录；不恢复授权、任务或审批，不撤销已执行操作。未发送文字保留，滚动锚点重置；已删除记录移除本页旧副本，后续新对话使用新 ID。默认 API 不允许丢弃未保存内容，须显式 `discardLocal=true`。读取失败、载入途中再次更新、本页内容变化或切换聊天/来源均保留原工作副本，不应用过时结果。

- 插件设置 `muyuHistoryEnabled` 新安装默认 true，排除在剧情配置档之外；既有用户明确关闭的值仍保留。启用后保存本页已有工作副本并读取旧摘要；关闭停止自动写入，不删除或隐藏已加载记录。未开启自动保存也可显式“加载／刷新本地历史”。
- 手动修改已保存记录的标题/归档状态和删除操作仍会写磁盘。关闭自动保存时，这些元数据操作不会顺便保存新的未保存回答；删除会明确删除磁盘和本页副本。
- 每次接纳问题、运行开始/终止后保存安全投影，不依赖 pagehide 才写。退出页面时最后一个未确认事务仍可能丢失，不能把异步清理等同于可靠后台执行。
- 设置保存需宿主确认；记录保存需 IDB transaction complete。失败保留工作副本、显示未保存并允许重试/导出。
- 冲突不自动合并/覆盖。先导出本页内容，再刷新核对其他标签页版本；重试不会绕过 revision。
- 刷新时，仅明确保存了自动启用选项的连接恢复模型配置；不会自动调用模型、工具或恢复 Run/资料授权。磁盘 running 状态读取为 interrupted；原任务是否在远端继续计算未知。
- 换连接、禁用和撤销权限清理运行态/产物，打开空白视图，但保留历史仓库。手动选择旧会话后，继续发送须重新满足历史所需授权；保守记录当时已有的全部数据类别，可能比实际读取范围更严格。
- 每个已创建会话分别保留本页输入草稿和滚动位置，切换/重挂视图恢复；不写磁盘。无新消息的进度更新不强制滚底。删除同时清除对应输入、滚动和运行缓存。
- 会话栏区分仅在本页、保存中、已保存在本浏览器、未保存和保存失败。保存状态仅描述历史记录，不证明宿主配置或聊天数据的持久化。
- 失败/取消/中断后，若末尾是独立的用户问题，可将其原文复制回空输入框；已有草稿不会被覆盖。此操作不调用模型、不重放工具、不恢复授权或旧任务。若原运行触及工具或冷启动后无法核验过程，界面要求先检查实际效果；不能将其称为安全的一键重试。

## 历史侧栏与管理

- 会话操作集中在左侧栏：顶部新建与搜索、折叠筛选、会话列表及底部导入。列表显示原始归属；各会话和顶部当前会话的 `⋯` 提供导出。齿轮保留持久化开关及隐私说明，不再承载导入导出。
- 窄窗打开或新建会话成功后自动收起侧栏；宽窗保持展开。按列表导出会先明确选中该会话，异步打开后若选中项已变化则不导出。

- 以浮窗内容宽度 680px 为分界，宽窗默认展示侧栏，窄窗通过“历史”覆盖展开。手动收起/展开优先于默认行为；窄栏支持 Escape 收回及可见控件的键盘循环。
- 默认展示本机同一 ST 账户的全部未归档会话，不按聊天存档或角色卡筛选；范围可选当前聊天/全局任务/全部历史，再按标题、任务类型、归档筛选。标题搜索只读摘要，不加载全部正文或调用模型。
- 统一助手记录可在切换 ST 聊天后继续；控制器卸载旧聊天运行会话，下一次发送绑定当前聊天，并向界面及模型说明资料目标已切换。旧分类任务、归档记录、导入备份仍遵守原只读边界；恢复归档不解除 imported 的只读限制。
- 每条记录及顶部当前会话均有折叠操作菜单。重命名、归档/恢复、删除使用显式确认表单。归档不释放存储；删除不可撤销，建议先导出，不影响 ST 原聊天。
- 对运行中的目标会话归档/删除，先取消并等待 completion 与 drained；其他会话的运行不受影响。若后续删除失败，已取消的任务不会自动重启，记录仍保留。
- 管理操作和自动保存共用串行队列；等待元数据保存期间新到达的回答保留在工作副本，随后保存。删除确认后清理本页缓存，迟到读取和保存不能重新创建记录。
- create 与 update 分开使用，update 必须携带已有 revision；目标缺失返回 HISTORY_DELETED。跨标签页旧写入不会复活记录。显式删除一个已经被另一标签页删除的记录只清理本页副本。

## 文件交换

单文件最多 2 MiB，只接受受支持的单会话闭合 JSON 格式；校验字段、版本、消息数量、大小及禁用原型键。文件选择只展示预览，确认后才生成新 UUID 的记录，不覆盖同 ID 旧记录、不信任导入的权限声明。保留文件中的原始 scope 作为说明，imported=true 固定只读，任何匹配当前聊天的文件也不能直接发送给模型。

JSON 为紧凑格式，可重新导入；Markdown 使用可信标题和逐消息字面量代码块，保留原文而不把 HTML/图片转换为活动资源。导出包括用户输入和最终回答，可能包含私密信息；不导出连接密钥字段、运行权限或工具执行记录。

## 容量与模型上下文

最多 64 会话、每会话 4096 条消息、单记录 32 MiB UTF-8、每账户磁盘记录合计 256 MiB。满额明确拒绝，不自动删除或裁剪历史；归档仍占容量，确认删除后释放容量。

发送前按实际序列化输入、最大支持回答（2 MiB）、摘要替换（512 KiB）及元数据余量预检，不再仅预留 200000 字节。空间不足不提交运行队列、不调用模型、不清空未发送草稿；整理摘要不会删除原文，因此不能释放存档容量，应导出并新建对话。

账户设置后端按单条 8 MiB、整库 32 MiB 提供同步 `assertCapacity`，由宿主适配器透传给发送预检。总量包括未加载的已保存会话与本页未保存工作副本，对同 ID 取较大体积，避免旧缓存低估并发记录；附加输入、回答和摘要预留后才允许运行。关闭自动保存不施加账户后端存盘预留；切换存储选择不改变当前已打开后端的限制，重开后才生效。预检不是跨标签页空间预订或持久化成功证明，保存阶段仍独立检查真实容量和 revision。

若最终安全投影仍意外越界，界面明确显示未保存，回答保留在本页并提供有界恢复备份。恢复 JSON 使用独立的 `muyu-unsaved-recovery` 格式，包含原合法记录与未保存消息，仅用于备份，不能当作普通会话重新导入；Markdown 保留逐消息字面量原文。不会放宽磁盘/导入上限、自动裁剪或覆盖原记录。摘要/元数据修改和重试保存不能清掉恢复内容，刷新前必须导出。

服务端满额时，可选浏览器迁移改为待处理状态，不阻断已有服务端记录的查看、导出或删除；浏览器原件保留。腾出空间后点击“加载／刷新本地历史”重试迁移。仅容量不足可降级为待迁移，其他存储/身份错误仍按原边界拒绝，不悄悄切换后端。

运行缓存最多 8 个会话，只有空闲后才可卸载旧运行缓存（含临时产物/过程），历史消息保留并按需重建。单控制器最多 1024 个在缓存中的 Task/Run；卸载释放占用。

生产控制器按上下文策略规划历史：默认 900000 估算 Token，预算内携带完整成功问答，不再限于最近 12 轮；模型文本上限 2 MiB 序列化 UTF-8，工具 DTO 仍为 32 KiB。底层 selectHistory 仅是独立应用门面的保守后备选择，生产控制器使用 planContext 替换它。失败/中断的孤立问题不重放，不把过大轮次切半，也不跨过过大最近轮次捡选更老内容。界面明确提示省略，不宣称这是精确 Token 统计或完整对话记忆。

## 验证边界

Node 测试覆盖存储合同、事务提交/回滚替身、账户空间、CAS 冲突、保存失败/重试、并发读取、跨聊天拒绝、授权撤销、刷新惯性、运行缓存释放和 GUI 控件；新增迁移、删除防复活、元数据/回答并发、关闭自动保存后的显式管理、只读导入、筛选、确认流程、容器响应式与焦点/滚动状态。

IDB 使用窄契约替身进行自动测试；不能替代浏览器原生配额/驱逐、隐私模式与多标签页实测。手动验收：开启保存→发送→刷新→手动选择旧会话；换账户；两个标签页编辑同一会话；切聊天/重建面板；320/400/600/800px。未运行真实模型请求或引入 Playwright。
