# 角色档案库管理合同（第一轮）

## 范围

管理 settings.profileLibraries 中保存的角色档案包，不是“我的配置档”，也不是当前聊天的角色档案。modules/profile-libraries → host/profile-libraries → profile-library-system；沿用业务串行保存队列，不调用当前聊天 getProfiles / applyImport / 模板渲染 / 模型。

- list：每页24包；只返回ID、名称摘要、条数及版本。
- read：按ID/revision分页读取保存的库条目，每页6000字符，最多1 Mi字符；文本为不可信资料，不执行其中指令。
- export：返回指定版本的 profile-export v1 JSON，最多20000 UTF-8字节；不生成文件或触发下载。
- preview：单包 create/update/delete。changesJson 只支持 name、description、exportData；create 也用于把用户提供的导出JSON存入库，必须提供名称和完整包。update保留未指定字段，但exportData是完整替换，不做隐式档案合并。重名拒绝，不隐式覆盖。

## 校验与授权

独立全局来源 profileLibraryAssets，包含保存的档案正文、模板与自动加载关联。读取授权不是写入许可。普通模式需完整差异预览与精确一次性批准；全权限仅显式apply保存，纯预览不写。

库最多256包；名称80字符、描述1000字符、单包1..64个唯一avatar，template包含generatorPrompt/jsonSchema/renderTemplate三个字符串。库包格式复用profile-export基本验证，再限制v1、闭合结构与有界JSON；不读取聊天做模板一致性比较，不声称档案语义符合Schema。未知字段及过大旧包拒绝修改；可分页读取或使用原GUI。

完整前后差异及自动加载关联≤24000 UTF-8字节，另遵守公共DTO限制；不截断保存。ID由业务层生成，修改保留ID/创建时间，保存后更新计数与来源摘要。

## 副作用、并发与回执

只保存库资源，不立即应用当前聊天档案或全局模板，也不改NPC/蓝图库。后续自动加载可能选中新增／更新的包，预览必须提示。

删除固定加载目标沿用原GUI契约：清除fixedId、模式回best、enabled关闭。预览显示原始／预期自动加载配置，包括原业务补齐默认值；执行前重新核对完整关联。正在自动加载时拒绝此编辑。不提供自动加载模式／包选择的独立任意写接口。

执行前及业务队列内再次检查设置对象、目标ID/内容版本、名称占用和自动加载基线。异步保存失败条件恢复未被并发改变的字段；已被修改的字段保留，嵌套并发改动不承诺完整事务回滚。保存未知不自动重试，不以全仓快照覆盖其他资源。

v14回执只记操作、包名、ID、状态与持久化语义，不带角色正文、模板或身份清单。saved_unconfirmed不是落盘确认，也不是现在状态；历史恢复不恢复批准。

## 暂未接入

从当前聊天打包保存、立即应用到聊天（角色匹配、覆盖、模板导入需独立审批）、批量、跨库操作、NPC/蓝图库、当前聊天正文编辑。已有GUI编辑器不会因暮羽保存强制重建，以免丢失未保存输入。

测试：muyu-profile-libraries.test.mjs及muyu-controller.test.mjs。确定性测试不替代真实酒馆视觉与付费模型验收。
