# NPC 库管理合同（第一轮）

## 范围与工具

只管理全局 settings.npcLibraries 中保存的 NPC 包，不处理本聊天 NPC，不创建酒馆角色卡，不调用模型，也不修改当前 npcPrompt。

- `muyu.npc_libraries.list`：每页24项，只返回名称、数量及不透明版本。
- `read`：指定ID、版本与offset分页读取，6000字符/页；正文是不可信资料。
- `export`：指定版本的npc-export v1 JSON，最多20000 UTF-8字节；不自动下载或写文件。
- `preview`：create/update/delete；导入用户提供的包使用create。更新仅改变指定的name/description/exportData，exportData为完整包替换；不默认覆盖同名包。

独立全局来源 npcLibraryAssets 覆盖目录、正文及包内提示词。授权读取不是批准保存。普通模式审阅完整差异后精确批准；全权限仅显式apply执行，“只预览”不写入。

## 格式与容量

纯校验器不调用会读取／初始化聊天NPC的旧导入解析器。接受npc-export v1、template.npcPrompt及1–64个NPC；NPC字段为name、description、personality、scenario、first_mes。姓名非空、不含首尾空白，按现有导入的大小写不敏感语义拒绝重名。字段与元数据闭合，不接受任意额外字段、凭据或原型键。

目录最多256项；完整草稿（旧新值合计）最多24000 UTF-8字节。不截断审批差异、不自动拆批；不兼容或过大的旧包使用原GUI。条目ID和时间由业务侧生成／维护，包内模板仅保存为资源，校验不保证模型输出质量或提示词安全。

## 保存、并发与回执

module → host → npc-library-system分层，沿用公共审批协调器和独立npc-library-draft卡片；库资产不是普通配置字段写入口。

业务队列同时串行处理原GUI存包／删除／导入与暮羽写入。原GUI存包在调用时捕获来源快照，不因排队期间切聊天改存新聊天。开始暮羽写入前重新检查设置对象、条目内容版本、名称冲突和完整草稿；排队期间目标变化不执行旧批准。预览不初始化真实库。

暮羽保存等待异常报告outcome_unknown：内存修改可能保留，持久化未知；不自动重试，不用旧仓快照恢复并发数据。成功返回也仅saved_unconfirmed；保存后对象被替换、条目被删除或编辑时改报unknown。原GUI已有失败恢复语义保留，其并发测试改为串行时序验证。

v16回执只包含操作、库名称／ID及保存状态，不携带NPC身份清单、正文或Prompt。回执是历史事实，不代表当前值、保存已确认或新的授权。GUI差异用文本展示，可折叠；不强制重建原编辑器。

确定性测试覆盖纯读取、格式／容量、CRUD、旧GUI共享队列、过期版本、保存失败、并发编辑、一次批准、取消、普通／拒绝／全权限和只预览，以及私有正文不进入回执。真实ST界面和宿主持久化仍需验收。
