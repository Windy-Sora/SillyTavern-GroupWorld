# 通用 Provider 执行合同

## 缓存结果检索

同一运行已产生的结果可经 `muyu.provider.search({id,revision,resultId,query})` 检索，再携带相同来源参数和 `matchToken` 调用 `muyu.provider.match`。它们只读该次执行的缓存，不再次调用 `render`；仍核验原执行来源授权、目标与共享字节预算，不恢复已清理结果。只有 Provider ID 不能触发隐式执行。原有结果分页及首屏输出契约不变。

## 当前入口

已注册 Provider 仍由原 `provider-registry.js` 管理。暮羽使用 `discover({offset})` 读取当前注册元数据；使用 `execute({id, revision, projection?})` 调用选定实例的 `render(context, signal)`。注册和执行之间没有每个脚本单独的适配文件，也不修改现有导入格式。固定来源 `list/read` 是另外一条可验证的只读通道。

用户导入的 Provider 由加载器私有记录上传源码的 SHA-256 摘要；发现版本还包含可选上下文声明的位标记。同一源码和声明在刷新后得到同一版本，源码或声明变化得到新版本。其他插件直接注册、没有可信源码摘要的 Provider 使用连接内随机版本；刷新后须重新发现，旧历史不能误认成同一实现。运行中另有实例标记，即使热替换成相同版本，晚到的旧实例结果也被丢弃。摘要只标识已上传资产源码，不证明外部依赖、运行时配置或输出恒定。

申请由模型提出，控制器核对当前注册表中的 ID/版本，用户界面只提供“允许本任务”或“拒绝”。执行工具的效果类别为 `external`，仅该工具 ID 可通过内部 Broker 例外；普通读取工具不能借此执行代码。工具到来源依赖和历史依赖统一在 `application/capabilities.js` 声明。

## 输入与输出

默认上下文包含最近50条消息的名称/正文/用户标记、当前群成员 ID；单聊时提供当前角色的名称和头像键，群聊没有单一角色。Provider 可选声明 `muyuContext: ['chatMessages']` 取得最近200条消息及 `chatMessagesLimited`，或声明 `['characterCard']` 取得单聊角色卡的有界字段。两项可组合；discover 的 `context` 与 `missingContext` 会说明当前聊天能否提供。未知声明不进入目录，缺少声明的旧脚本继续使用默认上下文。声明是上下文准备合同，不隔离同页 JavaScript 的其他访问。上下文构造位于 `host/provider-context.js`，新字段应在此集中增加并有明确容量与缺失语义。

`content` 投影接收字符串或 `{content}`；`data` 投影对 `{data}` 做有界 JSON 复制。一次结果最多131072字符，每次执行返回前8000字符、`resultId` 和 `nextOffset`。`muyu.provider.result` 用相同 ID/版本和游标只读翻页，不再次调用 render。结果只驻留当前 Run，最多四份且合计131072字符；Run 结束即清理。翻页与首屏都计入 Provider 字节预算，预算不足会明确返回 `BUDGET_EXCEEDED`。

异常只返回 `OUTCOME_UNKNOWN` 等安全状态，不泄露原始异常。返回的文本是 Provider 产生的不可信资料，不构成新指令或审批。执行过程中脚本有同页权限，故不能把它称作沙箱。超时、取消与聊天切换会阻止晚到的输出被采纳；已经开始的 JavaScript 副作用可能继续发生。调用者要根据实际 Provider 代码判断是否适合“只看不改”的要求。

## 审批与历史

授权键包含聊天、任务、Provider ID、版本。批准一个脚本不批准另一个；禁止“此聊天持续允许执行”按钮。任务结束或重连后执行权失效。历史依赖写为 `source:providerExecution:<id>:<version>`；授权到期后，助手不得再次把受影响的旧问答发给模型。新任务取得当前已注册的同一版本执行批准后才能重新带入。用户可始终本地查看/导出历史；导入不会恢复批准。结果翻页仍检查同一授权及原 Run/聊天归属。

## 将来 Agent 编写/测试的扩展点

1. 生成代码先存工作区草稿，标明将注册的 Provider ID、输入上下文需求、预期效果和输出合同。草稿本身不注册、不能执行。
2. 隔离测试只用合成宿主端口，记录输入、输出、异常和副作用观察。需要测试真实酒馆状态时另开显式操作，不把隔离测试结论当作无副作用证明。
3. 导入前展示完整代码和变更差异，并取得独立的用户确认。导入沿用现有用户资产加载器的归属和回滚合同。
4. 导入完成后重新 discover，实际 `render` 仍需上述具体版本的任务审批。编辑或重新导入会产生新版本，旧审批不能继续用。

已注册 Provider 执行通道保持不变。2026-10-03新增独立的[源码资产工作台](../provider-assets/README.md)，支持源码读取、新资产草稿、合成场景测试、批准导入及用户资产的精确版本替换／删除。系统内置及其他来源注册只读；用户导入和暮羽创建的源码资产均可管理。合成测试仅检查固定虚构场景，不证明真实运行无副作用；替换批准不授予新版本 render 的执行权。
