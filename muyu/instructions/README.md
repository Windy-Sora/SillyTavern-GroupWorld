# 行为偏好与指令分层

## 2026-10-06 固定回复语言

悬浮球齿轮 → 对话与显示 → 行为偏好 → 回复语言。默认关闭并跟随用户语言；可开启后选择13种常用语种，或选择“其他语种”填写自定义语言名称。界面语言仍独立选择，代码、JSON、引用与实际GUI名称要求保留原样。它与“启用补充指令”独立，使用同一保存/放弃/恢复默认流程；恢复默认需保存。

自定义编辑模式与语种文本分开：逐字输入 `English (US)`、`French Canadian` 时，中间值命中预设名称不会关闭输入框。仅初始化、明确切换、放弃或重置时重新选择编辑模式；不增加保存字段或模型指令。

现有 `muyuInstructionConfig` 可选增加 `replyLanguage: { enabled: boolean, language: string }`，旧的两字段配置无需迁移。保存的语言名称最多80字符，仅允许名称字符，不接受多行指令；有界无效草稿可保留供修改，但不能保存。任务指令DTO可选 `responseLanguage`，共享渲染器追加固定模板并计入真实请求预算，不新增模型调用、工具或权限。摘要请求不使用该模板。

保存从下一次新发送生效；已开始任务、权限/澄清续接和当前运行期内的任务方案批准保留原语种。语言快照不写入会话历史，历史导入或重启后不还原旧任务语言。仍属于模型行为引导，不能保证所有模型遵守，也不是回答后处理或自动翻译器。

## 2026-10-06 英文表达与续接

`behavior.js` 的固定 `RESPONSE_CHECKS` 由共享 `renderInstructions()` 写入每次普通模型请求的同一条 system 消息，覆盖工具续问、授权续接、无工具收尾和回执解释。显式用户语言要求优先；短追问沿用最近实质问题的语言，真正切换语言立即跟随。工具、技能、引用及宿主批准记录的语言不作为回复语言要求。英文使用英文GUI标签，不默认双语并列；用户正文、代码和JSON保留原文。人设不再提供可直接照搬的中文自我介绍例句，中文点缀只用于中文回答。

这仍是模型行为引导，不是语言检测器、回答后处理或安全保证。固定提示不进入会话存档或可编辑偏好，不改base/task/preference闭合DTO和4000字符限制；实际渲染长度由模型适配器计入请求字节与输入Token估算，超限仍在联网前拒绝。独立摘要请求没有普通回答指令，不注入该规则。

同时提醒模型：未应用只确认该预览未写入，不能断言当前值等于或不等于草稿值；应用后保存看真实回执。取消话题不代表删除卡片，关闭功能不代表故障，也不能保证只开一个开关就修好。Skill加载工具明确path必填，方案risks/unknowns明确每项最多200字符而非200词；校验和纠错次数不放宽。

片段检索指引仅加入普通 assistant 任务：区分暮羽会话历史与当前酒馆正文，局部问题先检索再核对原文，全面请求仍按范围完整读取，缓存 Provider 结果不重复执行。历史回执解释没有工具，不注入这些检索步骤或 selector 提示。

## 用户入口

齿轮 → **行为偏好**。全局配置 `muyuInstructionConfig = { enabled: false, text: '' }` 默认关闭，只控制暮羽的补充指令。基础规则和任务规则始终生效，不因关闭偏好而关闭。

支持启停编辑、保存、放弃修改、恢复默认（先恢复草稿，需保存才生效）。保存影响下一次发送，不改变当前 Run。文字最多4000个 JavaScript 字符单位、16000 UTF-8字节；超限不静默截断，保存禁用。为便于缩短已粘贴内容，允许有界超限草稿（最多16000字符，仍受32KiB JSON合同约束）。极端超大输入被拒绝并提示，保留之前的有效草稿。

草稿由控制器持有，切聊天、收起/重建浮窗和重新配置连接不会丢失；整页刷新不保留草稿。保存失败不替换生效配置，草稿仍在。保存等待期间继续编辑，成功只确认本次提交版本，不覆盖新草稿。

这是明文插件设置，启用时会发到当前模型，请勿填写密钥或敏感信息。不新增依赖，不修改ST核心，不提供模板变量、代码执行、多套预设或按聊天覆盖。

## 数据流和职责

1. `contract.js`：闭合配置/快照校验、长度限制、序列化。
2. `persona.js`：从 `assets/gd-assistant/character.json` v1.1.0 人设提炼的猫头鹰娘身份与温柔、好奇、轻俏语气，只控制表达。`behavior.js`：稳定的协作与表达规则，包含追问承接、实质歧义判断、基于契约的分析和简短介绍示例；`compose.js` 将两者与信任边界及现有 `modules/catalog.js` 任务规则组合，补充偏好单独标记。
3. `host/instruction-config.js`：确认保存、失败回滚，不覆盖同时发生的其他设置替换。
4. `application/controller.js`：编辑草稿、发送时固定指令快照；任务规则不再重复装入用户消息的 constraints。
5. `composition.js`：注入指令校验端口，core 仍只导入 core 内部文件。
6. `core/runtime.js`：每次普通/工具续问/预算收尾携带同一快照，历史裁剪不能删指令。
7. `model/chat-completions.js`：完成内部消息映射后，向最终 payload 前置且仅前置一条 system 消息；不改变内部消息索引、工具配对或私有思考回传。
8. `ui/instruction-view.js`：编辑及状态展示，不拼接模型请求、不控制权限。

指令快照版本1，字段为 base、task、preference。系统消息先写基础规则和任务规则，再以JSON字符串标注用户偏好。这种标注是模型行为引导，**不是安全隔离保证**；真正权限、工具范围与预算仍由代码校验。用户可以明确修订自己的剧情/业务条件，不能因此改动工具授权或突破运行预算。资料与摘要不升级为系统指令。

## 上下文、摘要与隐私

普通请求的基础规则包含任务交接边界：区分用户未完成目标、助手建议和未知信息，尊重新的取消/完成/范围收窄；不凭旧摘要复活已结束任务或虚构用户原话。仍可主动提出明确标注的建议，并拆分当前目标必要的实现步骤，不要求每个普通步骤重新确认。独立摘要请求使用相应来源分类规则，不携带这份普通请求指令；两者均不能授予工具权限或保证模型理解正确。

暮羽人设由受控的静态指令组成，不在运行时把角色卡或世界书直接提升为系统规则，也不套用普通角色卡“没有工具/看不到配置”的环境限制。普通回答、工具续问、预算收尾和回执解释共用这层身份；摘要请求仍不携带人设。耳羽动作、🦉与“咕”只是偶尔点缀，不强制每轮出现；代码/JSON不混入角色表演，授权、失败与风险说明不能被俏皮措辞冲淡。用户要求简洁、严肃或指定格式时优先遵从，工具权限和执行核验不变。

- 指令属于输入预算，最终请求计量包含它；界面单列 instructionBytes（已包含在总量中）。指令加当前问题仍超限时不发请求，不偷偷删规则。
- 手动和自动摘要使用独立摘要请求，不携带基础/任务/用户偏好，防止表达习惯干扰摘要职责。新偏好不重写旧摘要。
- 历史 DTO 仍为 v3，不增加指令字段；过程事件只含统计，没有偏好正文。不把指令直接写入对话、摘要或会话备份。模型若主动在回答中复述偏好，该回答仍属于普通会话文本，无法保证从中自动识别并删除。
- 剧情配置档正常快照不含此设置；JSON/ZIP 导入、导出与已存档配置应用均显式排除，避免意外传播或替换个人偏好。
- 其他兼容服务若不接受 system 消息，按原模型错误路径明确失败，不静默降级成 user 内容或丢弃规则。
