# 暮羽交互请求：澄清第一阶段

已实现 `muyu.interaction.ask` → 等待问题卡 → 用户显式回答 → 同任务续接。只澄清用户意图，不增加读取授权、操作审批、写工具或任意执行能力。模型说明不是授权，回答也不是授权。

## 分层和协议

- `contract.js`：闭合 Schema、语义验证、回答长度限制与可信交接端口。
- `modules/interaction`：内置只读控制工具，注册与权限校验仍经过 ToolBroker。
- `core/runtime`：仅消费组合层注入的交接端口，不依赖业务模块。成功的单独控制调用返回 `yielded` 终态、问题与安全文本；定时器、模型私有上下文和 drain 按原契约清理。并非长期挂起模型 Promise。
- `application/service` 与 `store.js`：创建可信请求 ID，绑定 session/task/run/target，管理 pending/answered/cancelled/expired、回答草稿和一次性消费。
- controller：校验当前视图、资料权限和历史容量，保留原任务字段范围及预算配置；GUI 只派发命令。

这是对原运行终态的显式扩展：交接不是成功完成任务，也不是失败。只有 `succeeded` 可以按原模块合同发布报告/草稿；`yielded` 不发布业务产物。运行中 `input_required`/`approval_required` 模型事件仍不接受，不从普通模型文字猜测工具调用。

## 硬边界

- 每次一个问题，最多600字符、0–3个不同建议，每个最多160字符；用户回答最多2000字符，可自由输入。空白问题/选项/回答、未知字段、恶意键拒绝。
- 澄清调用必须独占当前工具批次，混合批次全部不执行并返回纠错信息，受模型和纠错预算限制。
- 每任务最多三次澄清；第四执行段移除提问工具。澄清续接沿用起始预算配置，最多四段，因此该链路最大调用/执行时间/读取量均有界。等待时间不计执行超时；用户每次回答是显式续接，不自动开新段。任务视图累计各段开销。
- 回答先校验有效性、当前归属与运行槽；上游未 drain 时禁止续接；入队成功后才消费请求，失败不丢答案。模型收到原任务目标及用户澄清答案，不携带任何授权声明。
- 续接是新的执行段，不重放旧段工具调用或私有思考。原目标、已确认答案与预算内历史作为上下文；需要实际证据时重新读取并验证，不承诺保留完整旧工具轨迹。
- 设置开关或偏好更新遵守原契约；澄清链预算固定，新任务才使用新预算。回答不清空普通聊天框的其他未发送草稿。
- 会话切换保留请求，切回可答；关闭/重建面板保留回答草稿。酒馆聊天变化、归档/删除、更换连接、禁用或撤权会使原请求失效或销毁。切聊天前运行迟到的澄清不会成为新聊天可操作卡片。
- 问题以普通助手文本进入原对话历史；请求、回答草稿和控制状态只在内存。持久记录把交接标为 interrupted，刷新/导入只能看文本，不能恢复按钮、权限或执行。
- 请求容量由应用层会话/任务/运行上限和每任务三问限制；卸载会话释放其请求，应用销毁全部清理。

## 后续扩展

按需读取授权现已使用独立合同接入，详见 [权限合同](../permissions/README.md)。请求容器支持 clarification/permission，但草稿回答仅适用于 clarification，GUI 授权只能经独立入口处理；澄清三次上限不变，资料读取申请最多32次、Provider代码执行批准申请最多6次，三类计数独立。下述写审批仍未实现。

### 对话显示约定

新提交的澄清答案以用户原文进入对话历史与导出；关联问题及“回答不等于授权”的内部协议仅传给执行输入和任务约束，不显示为用户消息。已有历史不做文本猜测或改写。回答后隐藏问题卡；取消或失效只显示简短状态。累计执行开销放在会话工具中，不占用问题卡。

可复用请求身份、状态和视图机制，但 permission/action_approval 必须使用独立请求/答复合同和可信策略。未来写审批绑定原操作与版本，不能把重新生成的动作套用旧批准。本轮不照搬 Codex 的服务端等待通道，不实现自动审批或跨刷新任务恢复。

## 验证

`muyu-interactions.test.mjs` 覆盖协议、拒绝/批次隔离、yield/drain、去重及迟到返回；controller/panel 测试覆盖同任务续接、预算、三问上限、会话/聊天变化、归档、重连、选项只填草稿和重建。真实模型评测在独立 `muyu-agent-live-harness/interaction-run.mjs`，只用合成数据，不进入插件或 CI。
