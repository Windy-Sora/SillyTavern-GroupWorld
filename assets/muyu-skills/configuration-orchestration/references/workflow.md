# 成套配置的编排合同

## 1. 以用户目标组织任务

“弄个金币系统并激活”需要区分共享余额、角色余额、如何变动及何处展示，不能默认为写常量 Provider 就等于记账。“一套无限流配置”先提出最小可用的世界规则、状态变量和剧情蓝图，再根据已有资产决定改什么，不自动铺满所有模块。

已有上下文可以承接“开始吧”“照刚才的来”；不能仅因涉及多个模块重新要求分类。暂不明确但不影响边界的风格细节可以给提案；钱包作用域、破坏性替换、是否实际执行代码等关键分歧才澄清。

已有金币不自动等于用户新说的积分；已有变量、章节或同类Agent只能作为候选证据，不能把“复用更方便”当既定目标。用户明确要求独立系统时，保留旧系统、提出不同ID的新对象；不再反问是否沿用。目标确实含糊时说明“可复用／可独立”及差别，只问这个关键分歧，不要求重新分类。用户后续纠正优先于早先方案；不要在下一轮重新沿用已否定的对象。

## 2. 找工具并读取基线

使用 `muyu.tools.list` 查询工具组，再 `muyu.tools.select` 选用实际返回的组 ID；选择工具组须单独一次工具响应，下一次请求才使用新定义。没有选用不代表能力不存在，Skill 也不增加工具。

配置目录、合同和 Skill 不是当前值。普通参数按目录指定来源读值；记忆字段使用 memoryConfig，其他全局字段使用 configSettings。变量、蓝图、资源、Provider 等按各自返回的读取合同，不能编造 sourceId 或 selector。

跨来源可用 `muyu.task.plan` 提交明确只读方案。当前上限 12 个来源、8 个步骤；来源必须是工具允许申请的非代码来源。合同查询、分析、节点读取等只读动作都标为 read，不因主题是蓝图就标为写入 blueprint。

方案上的“当前不可执行”可能只表示没有进入该方案执行能力，不表示插件完全没有专用工具。批准来源仅授予读取，不授予修改或代码执行。授权拒绝后保留可完成的部分，不换其他来源绕行。

## 3. 精确整单适合哪些内容

### 已发布方案的证据关联

实际跨来源核对或同时落地变量与配置等不同操作时，先单独调用 task.plan，列最少的read与写入提案步骤；等宿主批准读取范围再继续。纯文字设计和简单单项预览不强制规划，不能为了关联多读资料。

Host task observation的taskState.plan提供artifactId、artifactRevision及steps.id。成功读取后，从readEvidence.evidence选对应本次来源／字段的实际读值证据，用可用的muyu.task.bind_read关联到对应read步骤。目录、合同、空／失败／单页结果不等于实际读值或读齐；不为每次合同查询增加关联调用。同一证据确实覆盖多个read步骤时可合并stepIds。

生成支持的配置／变量／整单候选后，用可用的muyu.task.bind_step传实际candidateId及匹配写入步骤ID。task.preview返回steps时，同时用bundleSteps:[{bundleStepId,stepId}]映射确实对应的子步骤。所有ID原样取宿主，不按序号、kind或标题猜身份；无法明确对应的项保持未关联。

同一份整单不等于同一种步骤：方案中新增金币定义使用variables步骤，修改自动记忆间隔使用settings步骤，脚本定义使用code步骤。不要用一个settings步骤统称“生成变量与设置合并预览”；每个实际子步必须映射到同类型的提案步骤。查询合同与汇总分析仍用read。类型不符时保留草稿并说明关联未建立，不篡改草稿类型、不重复原样关联、不把未关联说成已完成。读取来源还须覆盖每个专用预览实际所需的基线，目录与合同不替代这些来源授权。

只关联本任务当前批准方案版本；候选更新使用新ID。工具缺失、拒绝或预算不足时说明关联未建立，不虚构成功、循环重试或绕过审批。关联不证明用户意图、步骤完成、保存成功或新授权；执行仍看回执。普通答复不展示这些内部ID。

`muyu.task.preview` 支持普通全局 settingsJson、最多 6 个不同数值变量、最多 3 个明确请求的脚本定义。需要当前聊天目标，即使其中包含全局参数；没有聊天且只改普通全局参数，用单独配置预览。

划分前查询 `muyu.settings.contract` 的具体字段，按返回的 `bundle.supported` 判断，不按“记忆领域”一律拆单。自动提取开关 autoMemoryEnabled、间隔 autoMemoryInterval、总开关 memoryEnabled 和仅发言角色 autoMemorySpeakers 可进入普通 settings 整单；单角色容量 memoryMaxEntries 不可。可合并不意味着自动补开依赖或省略新基线核验。脚本定义也是这份整单的一部分，自定义Agent定义则不是；业务生成整单与配置整单是不同合同。

整单执行顺序为变量 → 设置 → 脚本定义，不是事务。变量的 global 表示当前聊天共用，不是影响全部聊天。脚本定义保存不等于当场执行，但 enabled 定义可能允许之后自动执行，应展示完整代码、触发条件与风险；不能仅因任务复杂就自行增加脚本。

这份整单的变量通道只支持聊天共享数值定义的创建／更新，没有角色目标选择器。三条按姓名命名的共享变量不等于真正逐角色变量；不能声称“六个额度够，所以每角色生命值可直接入整单”。逐角色定义、修改作用域、直接改存储值、删除或非数值类型仍走 variable_editor 专用流程。

以下不进入这份整单：memoryMaxEntries、storyBlueprintCompletionVariable、storyBlueprintEnabled、自定义 Prompt 总开关及 profileLibraryAutoLoad.* 特殊开关配置、世界书选择、Provider 资产、资源库和其他代码资产／密钥。以当前 schema 的完整边界为准，不将此排除清单解释成它们永远不能通过专用工具处理。

整单差异有容量限制，不能删除风险信息或截断代码来通过校验。超过数量、容量或类型边界时拆为可核对阶段；每阶段读新基线，再精确预览，不能把多个资产伪装成 settingsJson。

## 4. 其他资产分阶段

用户 Provider、自定义 Prompt、资源库、角色记忆、蓝图节点和当前聊天数据各用专用目录与编辑合同；不把“创建成功”“启用成功”“实际运行成功”混在一起。系统锁定 Provider 不修改。ST 消息编辑及其他未接入能力不能从可写配置推导出来。

代码阅读、隔离试验、导入注册和真实执行是独立能力。静态通过或合成试验不证明安全，也不能代替真实执行授权。用未来脚本自动化的方案需告知额外调用或后台副作用，不制造隐藏前置操作。

## 5. 批准、执行与结果

只读批准、精确草稿／整单批准、代码执行批准不可互代。正常模式使用真实宿主确认入口，不把用户聊天中的“同意”或旧回执当私有执行票据。

全权限模式不等于任意新任务都可自动应用：只有用户明确要求执行才按现有工具能力执行；“先预览”“不要应用”始终省略 apply。权限模式不能解除锁定资产、容量、基线及目标保护。

保存未确认、partial 或 outcome_unknown 后，停止剩余相关写入；已经确认的部分可能保留。报告“完成／未开始／未知”各项，不承诺整体回滚，不自动重跑整单。历史 diff 只描述当时提议，回执也不是当前配置。

核对版本：2026-10-05；`muyu/modules/task-plan/index.js`、`muyu/modules/task-bundle/index.js`、`muyu/host/task-bundle-draft.js`、`muyu/tools/selection.js`。维护路径不表示模型可访问本机源码；合同变化后修订正文并更新内置清单 revision。

定义保存、启用、实际运行、产物保存是状态层次，不是固定四次审批。依据实际字段合同和工具区分哪些已在同一精确草稿／整单内，哪些确实需要独立业务执行许可；启用与自动开关可属于定义候选，不能硬拆成四张卡。只讨论或预览不启动业务；一次定义批准不代表批准未来任意运行，也不保证自动事件已经发生。
