# 组合模式与反例

以下模式从本地插件源码与多份角色卡／预设样本归纳，核对日期2026-10-08。组件基线为ST-Prompt-Template manifest 1.17.4.1、JS-Slash-Runner manifest 4.8.13；样本仅静态检查，未执行脚本、未加载远程MVU或前端模块。不是所有版本的运行保证，也不是需要遵守的角色卡格式。

## 原生宏组合预设

多个提示词块可通过ST宏拼接文本。导出文件包含某提示词，不代表当前prompt order启用它；脚本还可能动态调整运行预设。提示词要求“调用搜索”不等于宿主提供搜索工具。先核对块启用状态、宏解释器与真实工具，不把文本宣告当能力。

## 正则驱动的消息前端

模型输出约定标签，正则替换成HTML，交互渲染器再承载UI。排查从原始输出、匹配条件到渲染环境逐段确认。并非所有前端使用MVU；状态栏也可能来自正文解析或浏览器记录。

立绘、表情、地点等可用字符串索引资源。若库只有“开心”，写“高兴”可能查不到图。应按这套卡的资源表核对，不把同义词归一化或重命名键当无风险润色。标签顺序、大小写、分隔符与嵌套是否重要，由解析器决定。

## EJS、变量与世界书路由

有的控制器读取正式状态，缺失时回退到开局临时变量，再决定加载哪些世界书条目。有的预处理逻辑按状态激活条目。因此“增加关键词”未必修复缺席：要核对变量路径、回退值、分支、条目标识和模板阶段。

禁用条目可能是初始化资料或动态加载目标，不应一律建议开启；但也不能反向断言“禁用一定正常”。核对这套框架的加载机制。读取模板文本不等于已经渲染，函数有读写副作用时尤其不能为诊断直接执行。

## MVU状态与自定义更新协议

MVU常见处理链为状态注入 → 模型输出更新指令 → 解析／校验 → 写入楼层状态 → 前端刷新，但单模型、额外解析模型和前端直接写入都可能存在。不能从一条“额外解析时使用”的说明推断当前启用了额外模型。

某些样本使用delta、insert、自定义move参数；某些更新路径相对于stat_data内部，而读取路径包含stat_data。它们不能未经核对改写成标准RFC 6902。检查实际解析器、Schema与更新示例；`_`或`$`前缀的含义也只是当地约定。

有的系统只存静态基线的差量：缺少NPC记录表示继承，不代表不存在。显示前会展开完整状态，保存时再压回差量。另有系统用十进制字符串表示金额。读到这些形式时先确认数据契约，避免补齐整个仓库或把字符串统一转成数字。

## 前端直接结算、模型负责叙事

重前端可承担地图、战斗、购买、技能解锁与任务领奖。按钮可能已完成余额检查、扣款、条目转移，再发操作通知；模型只需要理解结果。通知不是要求再次执行，叙事里说“领取成功”也不是实际变量已结算的证明。

例：模型把任务标为完成，前端领奖按钮才发奖励。排查“奖励没到账”应核对任务状态、是否点击领奖、余额变化与保存证据，不让模型直接重复加钱。软删除／回收站也可能是业务设计，不等于永久删除。

前端既可能绑定最新楼层，也可能绑定承载页面的特定消息。历史页面、swipe或切聊天后读错作用域会显示不同状态；先找真实选择器与绑定逻辑，不直接断言MVU丢档。

## 独立支线、浏览器存储与回注

小手机等支线界面可以单独请求模型，把记录按聊天命名空间存入localStorage，再将部分近期记录注入主线。酒馆消息、MVU状态、支线记录是三份资料，只读其中一份不能声称看到全局。

浏览器本地存储不是电脑服务器上的文件，也不天然跨设备同步。切聊天是否隔离、记录淘汰、导出与恢复取决于实际实现。前端按钮的额外模型调用可能有费用；不能把“刷新界面”当作必然无调用。

## 显示和上下文裁剪

某些正则隐藏状态占位符或较旧更新段；另一些把旧消息替换为摘要发送给模型，同时界面仍显示全文。深度过滤不能从“最新三楼”等名称推算，要核对字段及宿主语义。此路径与暮羽会话摘要、GroupWorld记忆压缩不是同一机制。

变量更新卡片可能只是把输出指令渲染成树或差异。只有展示代码而没有真实执行结果时，不能据“完成”标题推断更新已应用、通过校验或持久化。

## 陌生组合的处理原则

以上模式可组合，也可被自定义协议替换。没见过的标签或结构不等于错误；先对照生产者、消费者和当前证据。样本是帮助提出验证问题的案例，不是自动修复模板。不为适配新卡复制整份前端，不为补证据执行卡内代码。

陌生标签本身不能用于给缺失解析器、格式错误等原因排序；它可能是有效的私有协议。显示全文而发送摘要也可能是正常双管线，不能据此断言故障或自动纠正标签。只给与已知证据对应的核对方向。
