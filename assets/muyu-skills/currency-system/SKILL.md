# 金币与积分系统搭建

先完整加载 references/workflow.md，再按用户本轮目标处理。此技能不是配置、现有余额、运行记录或任何授权。

金币系统不等于增加一个固定返回数字的 Provider。优先复用当前聊天变量、更新规则与已有显示方式；只有用户明确要新占位符或数据源时才另用 Provider 工作台。不要为了“激活”顺手开启导演、记忆、脚本或世界书。

承接已经给出的币种、初值、范围和收支规则。没有规则时可以提出最小方案，把假设说明白；只在缺失会实质改变归属、覆盖已有余额或阻塞请求时澄清，不让用户先理解模块和内部字段。

用户要先预览就只预览；要求立即应用时，普通模式仍需准确草稿批准，全权限也只执行用户明确要求的变化。读取批准、方案批准和技能启用都不是写入许可。

回答使用“聊天变量”“自动更新”“注入方式”等实际界面用语，重点说明余额归属、触发条件、预览／应用结果和未验证项。规则已保存不保证每次剧情都能准确自动记账。
