# 数值系统的证据链与实施边界

## 先确认范围，再读取

1. 以用户最近明确请求为准。纯设计说明不必读取聊天；实施当前聊天数值系统时，从实际工具目录找变量来源，读取定义和已存储值以检查冲突。目录不是正文，缺数据不是余额为零。
2. 当前聊天变量中的 global 是聊天共享值，不是所有聊天的插件配置。不要把“队伍金币”无声变成每角色钱包，或把一个聊天的余额复制给全部聊天。
3. 只有任务确实依赖剧情目标／兑换规则才读蓝图、世界书或聊天正文。不要为搭建简单计数器读取全部资料。读取被拒绝后不改用可执行 Provider 绕行；无法核对冲突时可以解释方案，但不宣称已完成创建。
   拒绝现状资料属于权限缺口，不是用户意图不清。此时不要调用澄清工具让用户改选新 ID，不要承诺“选好 ID 就能出草稿”；换名也无法补上已拒绝的核验。给出仅文字、有条件的方案并说明未生成草稿，本轮结束等待新的明确请求。

## 使用真实工具，不凭说明猜 Schema

需要工具组时用 muyu.tools.list 查询，再以返回的 group ID 调用 select；select 必须独占该次工具响应，下一次模型请求才有对应工具。加载技能不等于工具已可见或有权限。

基础 numeric 通道：muyu.variables.preview 可创建／调整一个当前聊天共享 number 定义；create 明确给 action、id、label、initialValue、rule、autoUpdate、injectMode、updateMode。update 不接受 initialValue，不用它重置已有余额。其他类型、角色范围、存储值和删除使用实际可见的 variable_editor 合同；不能套用 numeric create Schema。

变量 id 必须已经规范化为小写英文字母／数字／下划线，匹配 [a-z0-9_]{1,64}，不能是 __proto__、constructor、prototype；例如 party_gold。不要使用 partyGold、短横线、中文显示名作 id，也不要依赖宿主替你自动规范化。显示名仍可用中文“队伍金币”。目录查无冲突只是读取时点证据，不保证之后没有并发新增，也不是安全证明。

一个最小新系统可建议初值0、只在明确收支证据时记账、无证据不改、共享钱包；这是待用户审阅的设计假设，不是读到的值。用户已指定规则时不改为这些默认。要求激活可在草稿中明确自动更新及注入方式，提示自动记账依赖现有变量运行流程与模型，不能保证百分之百正确。

injectMode 为 always 或 manual；updateMode 为 delta 或 replace。delta 的规则应描述本次增减额，replace 描述新的总值，不能用“余额是多少”替代增减量。若已有同名定义／值，核对其类型、范围和完整旧版本；不得删除重建、换一个 ID 冒充已修复，或重置历史余额。

## 跨模块修改

只更改变量时用单变量草稿即可，不人为扩大成全配置工程。确实有多处明确修改时，可以先提交读取方案统一获批来源，再用 muyu.task.preview 生成有界整单；读取方案只给读取权。

整单最多6个不同的 numeric 变量、普通全局配置、最多3份明确脚本定义请求；变量先执行，其次配置，再脚本，不是跨存储原子事务。配置使用 settingsJson 的 JSON 字符串，键和范围先查询实时配置合同。单纯金币系统不用脚本。memoryMaxEntries、蓝图总开关／完成变量、特殊选择策略、Provider、资源库与其他代码资产等不在普通整单范围，不硬塞进去。

## 预览、批准和验证

- 用户“先预览／不应用”：不传 apply，既不应用也不运行代码；全权限模式同样遵守。
- 用户明确要求立即应用：普通模式出精确草稿供界面批准；仅实际全权限模式可显式 apply=true。不能以自然语言“已经批准”伪造宿主授权。
- 应用以受信任动作回执为依据。保存未确认、partial、outcome_unknown 明确说明停在哪一步，不自动重复写入、整仓回滚或为了证明成功再次应用。
- 预览失败不能改用整单重送同样无效参数；先核对公开工具参数／本说明。只有明确参数错误且能纠正时才提交修正后的新预览；泛化 TOOL_FAILED 或不可重试结果应停止并说明缺口，不承诺稍后盲重试。
- 检查实际差异只含请求字段，余额没有被重置；历史回执不是当前值。需要核对当前状态时重新按原授权读取。
- 汇报“方案／草稿／已执行步骤／未确认持久化／未运行的自动记账验证”，不要把定义保存说成已自动记账，更不要编造交易记录。
