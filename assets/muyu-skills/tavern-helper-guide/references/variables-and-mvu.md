# 变量桶、消息版本与MVU

基线JS-Slash-Runner 4.8.13，核对2026-10-08；来源src/function/variables.ts、src/iframe/predefine.js。MVU本身是独立框架，未据此核验用户远程MVU版本；其协议必须从用户实际实现确认。

## 明确读取哪个桶

getVariables默认type为chat，返回克隆。chat来自聊天元数据；global来自全局扩展变量；character与preset来自对应配置存储；message来自目标消息当前swipe；script来自指定脚本运行数据；extension来自指定扩展设置。GroupWorld变量工具不自动等于这些桶的读取工具。

message省略message_id或使用latest时，该基线的读取选取最近非system消息；显式负索引则按原聊天数组取值。replaceVariables会将省略／latest转换为-1后写原数组末条。因此读取和写入的默认目标未必相同，尤其末条为system消息时；设计草稿尽量先明确楼层，不能用“latest总是同一个对象”解释。

上述latest差异仅属于message桶。用户问默认chat桶的局部更新时，重点解释整桶替换和保存语义；除非涉及message，别把消息选择器问题说成该操作必然遇到的故障。

getAllVariables是依上下文形成的顶层合成视图：global、character、脚本数据（脚本上下文）、chat；消息iframe还覆盖到承载楼层为止的消息变量。后面的同名键覆盖前面的，不是所有桶的无损深合并。它不等于MVU完整状态、所有聊天历史或GroupWorld变量仓库，不能直接把该合成视图整桶写回。

## 写入与保存不是同一件事

replaceVariables替换所选桶，不是局部patch；漏掉未要求的键会丢内容。updateVariablesWith读取克隆、执行更新回调，再替换结果；支持异步回调，但不是跨并发修改的原子事务。异步等待期间要考虑旧快照覆盖新值，不能从函数名称承诺并发安全。

message、chat、global等写入会安排对应的debounced保存。返回或await更新完成不证明持久化完成，也不证明Schema接受了全部业务含义。用户只要分析时不建议顺手调用初始化／整桶替换。

## MVU协作的最小证据

typeof Mvu 等绑定检查只能说明该上下文存在相应绑定，不证明具体框架顶层代码、初始化或更新流程已经执行；绑定也可能来自桩或另一份脚本。不要把一种常见更新标签或JSONPatch包装当作已核实的通用MVU协议，更不为概念问答附带更新载荷。

识别存储结构、Schema注册代码、初始值加载、实际更新解析器、事件、前端读取路径。stat_data、schema、display_data等名称可能出现，但不要凭一个字段就认定框架健康或完整结构。框架内部键不要用普通状态编辑随意重建。

区分模型维护、前端维护、只读派生字段。更新协议可能有delta／insert等自定义操作，路径可能相对于状态内部；只读前缀与日期／金额类型按该方案确认。Schema可以补默认、夹值、转换或过滤，因此模型输出合法JSON不证明数据全部按原样保留。

初始化条目被关闭可能是正常约定，但必须核对框架；不要统一开启。额外变量解析说明条目存在也不证明实际采用额外模型。变量更新结束事件与模型生成结束、UI渲染结束和保存确认独立。

面对基线＋差量、缓存或派生视图，先确定恢复与保存契约；字段缺席不等于对象不存在。若工具未提供第三方状态读取，只能解释已提供资料，不能把默认值或GroupWorld读取结果包装为MVU当前值。
