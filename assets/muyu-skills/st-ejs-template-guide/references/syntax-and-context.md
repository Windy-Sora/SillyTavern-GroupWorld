# 语法与执行上下文

## 先分清解释器

ST原生宏如`{{getvar::…}}`，EJS标记如`<% … %>`，GroupWorld DSL如结构化数据路径，是不同协议。某段文字可能先后经过多个解释器，但只有实际处理链能证明。不要把EJS片段直接写入不支持EJS的GroupWorld字段，然后声称能够执行。

EJS的控制代码使用`<% … %>`；`<%= … %>`输出值，`<%- … %>`用于原始输出，`<%# … %>`为模板注释；带下划线或短横线的边界标记用于空白裁剪。插件可定制escape行为，不能承诺`<%=`总是做标准XML转义，也不能把它当HTML清洗器。

用户明确要基础语法示例时，可用自编的无读写片段：`<% const count = 2; %>数量：<%= count %>`。这只是模板草稿，须放在该扩展实际处理的位置；不是已运行或已安装。复杂示例保持用户协议，不复制角色卡代码，不添加无关数据读取或写入。

## 执行环境由位置决定

prepareContext提供模板变量、角色与聊天标识、消息信息及绑定的辅助函数，并允许额外上下文覆盖。世界书条目环境可携带当前条目信息；消息处理环境涉及楼层与swipe。并非所有页面JavaScript、GroupWorld Provider或独立脚本都自动具有相同名称。

辅助函数包含变量操作、世界书读取、角色／预设文本读取，以及可执行斜杠命令等能力。这些是插件运行环境中的函数，不是暮羽工具目录。不要从“模板可以调用”推断暮羽现在能读到相应资料或具有执行权限。

## 阶段不等于唯一执行一次

插件挂接生成前、世界书条目处理、生成数据／聊天补全设置准备、消息创建与渲染等阶段；还兼容酒馆助手自定义生成事件。某段模板能否执行、是否改原始消息或只改显示，取决于位置与设置，不按“EJS只在发请求前运行一次”解释。

副作用放进模板可能在渲染、重建或其他阶段再次发生。用户只希望显示计数时不要引入增量写入；需要真实修改时必须理解触发条件与幂等策略。选择阶段是设计决策，不是把所有模板强制改为同一种标签。
