# 变量与动态世界书

核对基线ST-Prompt-Template 1.17.4.1，2026-10-08；来源src/function/variables.ts、src/function/ejs.ts。以下描述该基线，不能替代实际用户版本的合同。

## 变量作用域与缓存

setvar默认写message作用域，getvar默认从cache读取。可选作用域包括global、local、message、cache、initial；local对应聊天元数据，不是插件全局配置。EJS变量不等于GroupWorld变量系统的定义、默认值与逐角色存储。

预缓存以顶层覆盖合并global、initial、聊天变量、目标消息当前swipe变量，后者可覆盖前者；不是任意深度的完整状态合并。默认读取可能来自缓存，显式message读取也需核对withMsg和选择器，不能假定它一定直接返回承载消息中独立存在的值。defaults只是缺值回退，不证明该值真实存储。

例如真实存储为0与缺值后defaults为0都可返回0；单看结果不能识别走了哪一分支。即使确认本次回退，也不能据缓存缺席推断所有其他桶没有值。不从相等结果排序“更可能未写入”。

准备上下文会调用precacheVariables；该过程可能克隆前一消息变量并初始化目标消息。因此“只调用准备函数／getvar”不必然无状态变化。不要让暮羽为了只读排查直接执行这些函数。

message与swipe决定状态版本。withMsg可选择消息；具体查找／回退行为按实现核对。incvar等操作还区分读取和写入作用域。需要修复时先确定原桶与目标桶，避免把缓存合成视图整体写回消息。

消息版本不同不保证值永远隔离：准备过程可能克隆之前消息的变量。不要断言写入当前消息后新消息必定看不到，也不要把cache整份复制当持久化方案。

特别注意：变量选项`dryRun: true`在该版本表示允许准备阶段写入；实现会在准备阶段且未设置此选项时阻止写入。它不是“模拟而不保存”。`noCache`也不等于纯只读模式。

这条保护只针对变量写入函数，不是整个prepareContext的无副作用保证。未传dryRun也不能据此排除预缓存的克隆和初始化；必须分别解释准备函数与setvar的行为，不把一处保护推广到整个流程。

## getwi不是原始正文读取

该基线支持按条目标识读取当前世界书，以及指定书和条目的形式。绑定实现接受`getwi(entry, data)`或`getwi(book, entry, data)`；实际匹配方式和书名上下文须核对，不猜UID、标题与注释可互换。

data是传入模板的上下文数据：绑定函数将其与当前上下文及world_info合并后交给evalTemplate，不是渲染器options参数。不要把同名data概括成任意API的选项对象。

getwi找到条目后会处理原生宏、世界书正则和EJS，再返回结果；还可能采用运行时覆盖内容。无条目时返回空字符串并记录警告。空返回不能单凭结果区分未找到、空正文或渲染成空；源码中的书存在也不证明该上下文查到了它。

确认当前正文为空也只证明当前为空，不证明过去有正文或发生过清空；重新导入是否适合还需历史／备份及实际原因证据。

EJS可据变量读取不同条目；预处理逻辑也可参与条目激活／条件过滤。条目关闭可能是这套方案的动态加载安排，不能一律要求启用。@@preprocessing、@@if等扩展语义与ST原生关键词触发不同；先核对当前条目、阶段、设置和实现。

精准示例需保持最小证据链：模板运行位置 → 变量桶与路径 → 读取条件 → 条目标识 → 返回文本。未知条件只给条件性解释，不声称条目已进入最终网络请求。静态读取世界书工具与执行getwi不是等价能力。
