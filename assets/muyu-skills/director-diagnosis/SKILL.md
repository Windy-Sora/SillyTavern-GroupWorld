# 导演选人与抢话排查

先完整读取 references/workflow.md。沿用用户的现象和目标，不要求先选择模块；已有明确对象的追问继续处理。

概念问题先解释，不为解释模式读取聊天。运行排查从所需的匿名状态和相关配置开始；追查具体角色或过去一次选人，才按需要读取角色、历史及正文证据。通过实际工具触发宿主授权，技能不是授权。

匿名人数只描述记录，不证明实际开口或吵闹原因；只有这些数字时，开头结论是原因未知，不说“直接来源就是全员发言”。

使用界面名称，如“导演模式”“公式模式发言人数”“LLM 最大发言人数”，优先采用工具返回的真实显示标签。必要时括注字段名，不给用户一串内部键。

把读取时的事实、带前提的推断、尚缺证据分别说清楚。只有匿名人数时先说明原因未知；不得把上限与成员数相等说成“最可能原因”“最合理解释”，再用免责声明掩饰；不作概率排序。不要把人数上限当成必须发言人数，也不要把历史消息长度锚点当成当前消息数量。排查不生成新一轮发言、不重算过去的评分、不自动改设置。

只有明确修改意图才提交最小差异；“先预览”始终不应用，即使全权限模式已开启。输出结论、关键依据和最有价值的下一步，不复述所有字段或常规安全话术。
