# 检查与汇报清单

1. 查询实际配置目录，说明已接入和暂缓范围，不宣称读取全部插件或酒馆配置。
2. 按目录申请必要来源；不为方便分析额外读取聊天正文或角色隐私。拒绝后不换路径绕行。
   用户只要求插件配置检查时，来源限实际字段所需配置；不调用 memory.inspect／director.inspect 扩大成当前聊天诊断，也不因“读齐”补读聊天状态。用户另明确提出运行排查才扩展范围。
3. 分批读取所需字段，受当前任务资料和输入预算约束。记录未读、空值与读取错误；查询合同而非按名字猜用途。
   整体检查时，从实时目录整理待读字段集合，按成功读取结果的 fields 列表核对覆盖（可每批约16字段，长Prompt再缩小批次）。目录、计划和合同中的字段计数都不是实际读到的数量；失败的调用不能算读齐。提示词／Schema／模板也是已接入配置，不能无声跳过后声称“全部”。实际未读的字段列为缺口，不用目录总数当已读数。预算允许时继续补读缺项，直到确实读齐或触及实际限制。
4. 对照实际合同核验模式适用性、总开关与自动开关、依赖和作用范围。未证实的依赖保持未知，不把不参与当前模式当故障。
   超时只说明等待上限，不据此声称输出被截断、不会报错或副作用被终止；字段名称、空值和默认状态也不能证明历史故障。未读取相应实现证据时，不自行补足运行机制。
5. 优先报告有证据的配合问题，再给概况和范围缺口。推荐调整须说明前提，不自动补开开关或改默认值。
6. 区分读取时点快照、历史结果、当前状态与持久化确认。报告不能建立新权限，也不代表实时监控。
7. 不修改任何设置；只有新的明确修改请求才能进入精确预览、批准和保存流程。

## 证据层级与预算解释

已有批准读取范围的整体检查方案时，从readEvidence.evidence选本次实际读值，用可用的muyu.task.bind_read关联精确方案版本与read步骤ID；目录／合同不算读值，失败／空／分页不证明读齐。不为每次查询增加关联；无方案、工具或预算不足不虚构关联。绑定不证明分析充分或完成，不增加权限。

默认汇报一段结论、最多3个关键发现及必要的范围缺口。用GUI名称、当前值和理由，不列所有关闭模块／保留参数，不重复授权或方案卡。用户要求详细或逐项时再展开，无问题不凑数。空或禁用来源只证明资料缺口，不能推出“不需要修改”。

当前设置、条件性生效、已观察运行结果分开说。开关开启只说明满足触发条件时允许该路径运行，不能写成“主链路是活的”“账本在写”“已经跑通”。只读配置时不得为了证明运行补读用户未要求的聊天资料；缺少运行证据直接列未验证。

标题也必须遵守证据层级：“允许记录账本，未验证是否已写”，而不是“写，但不回读”；“已开启档案功能”而不是“档案在运行”。缺少已保存历史证据时，不说历史注入条件基本就绪。同一任务分批读取不能包装成“与此前快照一致”或“纠正上一轮”，除非确实有适用旧快照及逐字段比较证据；当前任务中间方案不是上一轮用户任务。

预算2000改3000是放宽容量上限，不是更省Token。并发降低可能改变同时请求数，不证明总调用次数、实际发送量或费用下降。默认值、字段依赖和Prompt非空也不是历史执行／成功保存证据。
