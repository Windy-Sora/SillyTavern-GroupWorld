# 蓝图工作流与操作边界

## 1. 先分清状态与目标

纯设计可提出章节和节点内容；不声称已经写入。分析现有剧情需读取相关正文，调整已存蓝图需读取蓝图。不得把“没开启蓝图”说成“没有保存节点”，也不得把空蓝图说成“故事没有推进”。跨聊天生成／旧面板状态不证明当前聊天内容。

通过真实工具目录发现并选用相应工具组，使用返回的 selector、revision 与分页游标。结构快照、节点内容和进度资料可能有不同授权，按实际来源申请；拒绝不改用其他 Provider 读取同一份数据。

## 2. 修改节点文字

现有 `muyu.blueprint_node_editor` 的 list／read／preview 使用 `blueprintNodeEditState`。列表选择器如 `blueprint-node:N` 只对当前快照有效。分页读齐需要的正文后才提交差异，不能把截断内容当完整节点。

文本预览仅修改 title 和 content 的已有字段，并保留其顶层类型。数组／对象字段整体替换，不是深度合并或自动追加；重写前保留未点名内容。节点 id、type、children、顺序、顶层标题／元数据与完成进度不属于此文本接口。完成条件的文字改了，不等于完成标记被推进或重置。

## 3. 增删或移动结构

先用 structure_read 分页读取完整树、各模式／层级进度和兼容完成变量，再用 structure_preview 提交一个 create／delete／move。来源为 `blueprintStructureState`，适用于已存在的蓝图，包括空树。

- create：`{parentId,index,node:{id,type,title,content}}`，一次创建一个无子节点节点，parentId 空串表示根层。
- delete：`{nodeId}`，删除整棵子树，不是只删标题。
- move：`{nodeId,parentId,index}`，index 是先移除原节点后目标列表的零基插入位置，不能移入自身或后代。

id 必须唯一、非空且不超过 128 字符，不自动替换冲突 ID。当前结构限制最多 256 节点、深度 8；完整树／进度前后差异还受 24000 UTF-8 字节限制。超过限制就缩小操作，不能截断数据让预览通过。

结构对齐采用连续完成前缀规则：插入、移动、删除可能丢弃后续完成标记，要展示各模式／层级真实前后差异。兼容完成变量存在时可能重置为 false；缺失不自动创建，锁定、类型或作用域冲突须停止。不要把结构变化说成只影响外观。

## 4. 从未建立的蓝图开始

initialize_read 只读并返回 canInitialize／revision。initialize_preview 使用空对象 changesJson，只适用于完全没有蓝图的情况；已有空树不是未建立。

初始化与界面建立空白蓝图一致：创建一个默认章节，并处理旧进度／通知／归档和兼容完成标记。它不是任意 JSON 整体导入，不自动启用蓝图，不调用业务模型，也不自动加载资源库。

用户要求“一套无限流蓝图”时，可以先给创作方案，随后按现有初始化、单节点结构和文本编辑能力逐步落地；不能承诺一次批准就写入任意整树。资源库应用和模式／层级进度修改必须另查专用工具合同，不用文本接口伪装实现。

## 5. 保存与扩展

面板未保存的编辑草稿不是已存蓝图；读取工具不能声称看过或保存了它。聊天／revision 改变后重新读取并预览。已保存、内存更新、部分完成、结果未知要分别说明；未知结果不重复执行，也不拿旧整树覆盖并发更新。

蓝图功能开关等配置与节点、结构、资源库、业务生成是独立操作。整单配置工具不包含蓝图结构或总开关；能力以当前目录为准。此前未接入的业务生成／续写不能靠 Skill 增加执行能力。
