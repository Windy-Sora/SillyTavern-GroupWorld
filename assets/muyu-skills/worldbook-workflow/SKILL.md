# 世界书与酒馆资料核对

EJS可按变量动态读取或过滤条目，这与ST关键词路径不同。涉及getwi、@@preprocessing或条件模板时加载“EJS提示词模板”；正则／前端／MVU共同影响时用“角色卡与预设协作分析”。静态世界书正文读取不等于执行getwi，不能用绑定或候选命中证明最终注入。

先完整读取 references/workflow.md。先分清 ST 绑定／激活、资源库正文和 GroupWorld 读取选择，避免用一个开关解释所有世界书路径。

按资料目录和 readHint 阅读元数据、必要单书或条目。目录有书不等于模型看到了条目；关键词和绑定也不能证明实际注入。用户只问一条设定，不读取整个库全部正文。

GroupWorld 选择与 ST 资源编辑是两个独立范围。世界书条目的增删改、创建空书、复制书，以及酒馆全局激活列表／当前聊天绑定和无已知引用的整书删除，可用专用工具精确预览；共享资源会影响其他聊天。角色／Persona绑定、整书重命名和预设写入尚未开放。没有公开的读取能力明确说明，不虚构后台日志和最终 Prompt。

用“世界书来源”“手动选择的世界书”“角色绑定”等真实界面词；字段名仅辅助定位。结果区分本次观察、缓存可能性、已知状态与未知注入。

Persona 目录只反映当前清单与选中项：只有一项也不能排除过去选错或其他身份来源。保存描述很短只能陈述文字较少，不能断言或排序为身份异常的原因。当前／保存参数或模板有差异不证明未保存、操作历史或最终注入；未返回的允许字段不等于工具不支持。具体资料以读取结果的 evidence 范围为准，标题与开头同样不能越过这些边界。

用户说“我换身份”“我选的身份写了什么”，通常指酒馆用户身份Persona。先承接该对象，按名称目录与独立描述入口核对，不因当前是群聊就改成导演选人；“那保存的和现在一样吗”继续对照同一身份，而不是刚好查过的其他工具。确有歧义且影响来源时只问一个短问题；若之前查错对象，承认只查了无关状态，再回到原目标，不据此断言原目标不存在。明确的发言角色、NPC或剧情身份问题不能强行改成Persona。
